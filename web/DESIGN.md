# Дизайн-гайд консоли Managed Valkey

Гайд описывает правила оформления консоли. Значения токенов живут в коде и здесь
не дублируются:

- [src/app/styles/tokens.css](src/app/styles/tokens.css) — все значения: палитры,
  семантические токены обеих схем, типографика, отступы, радиусы, тени, каркас;
- [src/app/styles/theme.ts](src/app/styles/theme.ts) — тема Mantine, ссылается на
  токены и задаёт варианты кнопок;
- [src/app/styles/tailwind.css](src/app/styles/tailwind.css) — те же токены в
  виде темы Tailwind (`bg-h3-bg-1`, `text-h3-text-2`, `p-h3-md`);
- [src/app/styles/mantine.css](src/app/styles/mantine.css) — переменные полей,
  которые тема Mantine задать не умеет;
- [src/shared/config/variants.ts](src/shared/config/variants.ts) — имена
  вариантов кнопок.

Система унаследована от консоли h3llo.cloud. Значения токенов взяты из её
собранной темы, а правила из наблюдений за живыми страницами. Где консоль
Managed Valkey отступает от того снимка, это перечислено в разделе
«Отличия от исходного снимка».

## Три правила, если читать некогда

Цвет берётся из семантики, не из палитры: `h3_text_2`, а не `#6E6E6E`. Тогда
тёмная тема получится сама.

Главная кнопка использует вариант `h3_accent`, и красить её вручную не надо.
В светлой схеме она чёрная, в тёмной мятная, и это разные цвета за одной
переменной.

Мята означает состояние и деньги, а не действие: выбрано, включено, столько
стоит. Кнопку «сделать» она заливает только в тёмной схеме.

## Цвет

### Два слоя

Примитивы: три палитры по десять ступеней, `h3_gray`, `h3_dark_gray`,
`h3_mint`. Это сырьё. В разметке компонентов они не появляются, кроме редких
случаев, где нужна конкретная ступень (тёмная точка внутри выбранного радио).

Семантика: токены вида `h3_bg`, `h3_text_2`, `h3_border_accent`. У каждого два
значения, для светлой и тёмной схемы. Переключение происходит по атрибуту
`data-mantine-color-scheme` на корне документа. Компонент, написанный на
семантике, получает тёмную тему бесплатно. Хардкод hex в компоненте считается
ошибкой ревью.

`h3_gray` обслуживает светлую схему, `h3_dark_gray` тёмную. Ступени у них не
зеркальные: у тёмной палитры середина смещена, чтобы поверхности `#272727`,
`#373737`, `#414141` отличались на глаз.

`h3_mint` первичный цвет темы. Заливка берётся со ступени 3, наведение со
ступени 2. Ступени 6–8 в интерфейсе почти не встречаются, это резерв на случаи,
где мяте нужно быть тёмной: текст на белом, иконка внутри светлой мятной плашки.

### Семантические токены

Значения в `tokens.css`, здесь только роли.

| Токен | Роль |
|---|---|
| `h3_bg` | фон страницы и карточек |
| `h3_bg_1` | приподнятый блок, панель расчёта |
| `h3_bg_2` | заливка второстепенной кнопки, наведение |
| `h3_bg_3` | наведение на пункт навигации, нажатое состояние |
| `h3_bg_inverse` | заливка главной кнопки в светлой схеме |
| `h3_bg_inverse_1` | наведение на неё же |
| `h3_bg_accent` | выбранное состояние, плашка цены, точка радио |
| `h3_bg_accent_1` | мягкая подсветка блока и текущего пункта навигации (в тёмной схеме полупрозрачная) |
| `h3_bg_accent_2` | наведение на акцентную поверхность |
| `h3_text` | основной текст, заголовки |
| `h3_text_2` | вторичный текст, подписи, описания |
| `h3_text_1` | плейсхолдер, неактивное состояние |
| `h3_text_inverse` | текст на инверсной или мятной заливке |
| `h3_text_accent` | акцентный текст, ссылки |
| `h3_text_accent_1` | акцентный текст на тёмном |
| `h3_border` | разделитель, граница шапки, декоративная рамка |
| `h3_border_1` | усиленный разделитель |
| `h3_border_control` | граница поля ввода и другого контрола |
| `h3_border_focus` | граница поля в фокусе |
| `h3_border_accent` | заполненная часть слайдера, выбранная карточка |

`h3_text_1` и `h3_text_2` легко перепутать по именам, а разница между ними
принципиальная: `_2` темнее и годится для читаемого вторичного текста, `_1`
светлее и предназначен для того, что читать не обязательно.

`h3_bg_accent_1` единственный акцентный токен, который в тёмной схеме не
повторяет светлую: плотная `#E4FFEF` на тёмном фоне выглядела бы белым пятном.

### Асимметрия акцента

Кнопка основного действия использует переменную `--h3-variant-accent`, и она
указывает на разные цвета: в светлой схеме заливка `h3_bg_inverse` с белым
текстом и наведением `h3_bg_inverse_1`, в тёмной заливка `h3_mint-3` с тёмным
текстом и наведением `h3_mint-2`.

Мята в светлой схеме отвечает за состояние и статус, но не за главное действие:
на белом фоне она слишком светлая, чтобы нести белый текст, и слишком заметная,
чтобы конкурировать с чёрным. Отсюда правило: не заливай кнопку мятой вручную,
возьми вариант `h3_accent`.

### Рецепты

Обычная страница: фон `h3_bg`, текст `h3_text`, подписи `h3_text_2`,
разделители `h3_border`.

Блок, который надо отделить от фона: `h3_bg_1` без рамки. Если рамка всё же
нужна, `h3_bg` плюс `h3_border`, но не оба приёма сразу.

Состояние «выбрано»: рамка `h3_border_accent` плюс подложка `h3_bg_accent_1`.
Только цветом состояние не передаём: у выбранного элемента должен быть ещё и
признак формы (точка радио, галочка, положение переключателя).

Деньги: сумма идёт обычным `h3_text`, мятой подсвечивается только бонусная
часть.

Опасное действие: в теме есть `--mantine-color-error` (`--h3-error`),
собственного `h3_*`-токена для ошибки нет. Если понадобится палитра статусов,
её придётся заводить: сейчас единственный статусный цвет системы мята, и она
означает «хорошо».

## Типографика

Текст и заголовки набираются Manrope, технические значения (идентификаторы,
адреса, версии, всё, что пользователь может скопировать) моноширинным Roboto
Mono. Оба шрифта подключены как variable-font из пакетов `@fontsource-variable`.
Заголовки отдельного семейства не имеют.

Начертания: 450 для основного текста, 500 для хлебных крошек, 600 для подписей
полей и названий в карточках, 700 для заголовков. 450 вместо привычных 400 не опечатка: Manrope
переменный, и на светлом фоне чуть более плотное начертание читается ровнее.

Интерфейсная шкала из пяти ступеней с интерлиньяжем в пикселях, а не
множителем: так высота строки предсказуема в плотных таблицах.

| Токен | Размер | Где применяется |
|---|---|---|
| `h3_xs` | 13px | подписи разделов навигации, служебные кнопки |
| `h3_sm` | 15px | хлебные крошки, строки расчёта, вторичный текст |
| `h3_md` | 17px | подпись поля формы, основной текст |
| `h3_lg` | 19px | подзаголовок блока |
| `h3_xl` | 21px | заголовок третьего уровня |

Заголовочная шкала `headline_xs`…`headline_xl` (25–50px) с относительным
интерлиньяжем около единицы: заголовки набираются плотно.

Карта заголовков: `h1` = `headline_sm`, `h2` = `headline_xs`, `h3` = `h3_xl`,
`h4` = `h3_lg`, `h5` = `h3_md`, `h6` = `h3_sm`. Начиная с `h3` заголовки берутся
из интерфейсной шкалы: внутри страницы заголовок третьего уровня это подпись
группы, а не самостоятельный титул. Все заголовки переносятся с
`text-wrap: balance`.

Правила набора:

- основной текст не опускаем ниже 13px, и эта ступень только для служебных
  подписей;
- числа набираются с неразрывными пробелами в разрядах и перед единицей:
  `1 926,00 ₽`, `2 ГБ`;
- длинный текст в узких контейнерах обрезаем многоточием, а не переносом:
  хлебные крошки и названия ограничены 200px каждое, многоточие в конце
  сохраняет начало имени.

## Отступы, радиусы, тени, границы

Шкала отступов `h3_xs`…`h3_xl` (8, 12, 16, 24, 32px) не степенная: шаги растут
мягче удвоения, потому что на плотных экранах между 8 и 16 нужен промежуточный
шаг. Применение: 8px зазор между иконкой и подписью и между кнопками в группе,
12px внутренний отступ строки списка, 16px внутренний отступ карточки и зазор
между полями, 24px между группами полей, 32px между разделами страницы.

Значения вне шкалы допустимы только в макете страницы, не внутри компонентов:
заголовок страницы отбит сверху на 64px и снизу на 48px, низ страницы имеет
запас 120px. Строка со слайдером занимает 60px, строка с обычным полем 42px.

Радиус по умолчанию `h3_sm` 6px: кнопки, поля, панели. `h3_xs` 4px для мелких
плашек и индикатора сегментированного контрола, `h3_md` 8px для слайдера и
карточки выбора, `h3_lg` 12px для крупной карточки, `h3_xl` 16px для
модального окна, `h3_full` для аватара и точки радио.

Теней две, и обе используются редко. `h3_default` поднимает всплывающий слой
над страницей: выпадающий список, поповер, меню. `h3_primary` добавляет мятное
свечение для элемента, который надо выделить как активный или рекомендованный.
Иерархия строится не тенями, а поверхностями `h3_bg` → `h3_bg_1` → `h3_bg_2` →
`h3_bg_3`. Тень означает «этот слой оторвался от страницы».

Толщина границы везде 1px. Даже там, где границы нет, компонент объявляет
`1px solid transparent`: так кнопка с рамкой и без неё имеют одинаковый
габарит, и при наведении ничего не дёргается. Разделители используют
`h3_border`, контуры интерактивных контролов `h3_border_control` (см. раздел
«Контраст»).

Консоль плотная: строка навигации, строка расчёта и поле формы занимают
минимум вертикали. Не переносите сюда разреженный ритм маркетинговых страниц.

## Каркас и сетка

### Точки изменения раскладки

| Имя | Значение | Что происходит |
|---|---|---|
| `mobile` | 768px | граница мобильной вёрстки |
| `tablet` | 1024px | появляются боковые панели, исчезает нижний футер |
| `aside` | 1280px | правая панель перестаёт быть выдвижной |
| `wide` | 1408px | боковые панели расширяются с 256px до 280px |

Имена заведены поверх стандартной сетки Mantine (`xs`…`xl`), чтобы в коде
читалось намерение, а не число. В Tailwind те же имена доступны как варианты
`tablet:` и `wide:`.

### Оболочка консоли

```
┌──────────────────────────────────────────────────────────────┐
│ header 52px: хлебные крошки слева, управление справа         │
├────────────┬────────────────────────────────┬────────────────┤
│ navbar     │ main                           │ aside          │
│ 256px      │ container 784px по центру      │ 256px          │
│ (280px     │                                │ (280px         │
│  от wide)  │                                │  от wide)      │
│            │                                │                │
│ логотип    │                                │ расчёт         │
│ разделы    │                                │ стоимости      │
│ ─────────  │                                │                │
│ баланс     │                                │                │
│ профиль    │                                │                │
└────────────┴────────────────────────────────┴────────────────┘
```

Навигация, правая панель и футер имеют границу со стороны контента. У шапки
границы нет: строка крошек не отделяется от страницы, к которой относится.
Внутренний отступ оболочки нулевой: поля создаёт контейнер контента, панели
прижаты к краям окна. Ниже `tablet` навигация и правая панель становятся
выдвижными, внизу появляется футер 52px с логотипом и бургером. Правая панель на
мобильном закрыта по умолчанию.

Размеры каркаса лежат в токенах `--h3-header-height`, `--h3-navbar-width`,
`--h3-navbar-width-wide`, `--h3-container-page`.

### Сетка формы

Форма двухколоночная: подпись слева, контрол справа.

- подпись это `Input.Label` кегля `h3_md` и начертания 600, а не обычный текст:
  так подписи полей, слайдеров и групп выбора набраны одинаково;
- рядом с подписью стоит иконка `info` цвета `h3_text_1` с подсказкой при
  наведении и фокусе с клавиатуры;
- колонки равны по ширине от 768px: контрол занимает правую половину
  контейнера, а не всё место, оставшееся от подписи. Так правый край полей,
  слайдеров и кнопки отправки совпадает при любой длине подписи;
- контрол растягивается на всю ширину правой колонки, включая кнопку
  отправки: она стоит в строке с пустой подписью;
- поле берёт размер `md`: высота 42px, поля 14px, кегль 16px. Размер `sm`
  оставлен второстепенным формам;
- вспомогательное действие (сгенерировать имя) стоит справа от поля отдельной
  иконочной кнопкой варианта `h3_stroke` размера `input-md` или `input-sm`,
  чтобы её высота совпала с высотой поля;
- поле, которому нужна вся ширина строки (группа карточек выбора), выносится в
  полноширинный слот, и подпись встаёт над ним.

Группа радио-карточек раскладывается адаптивно: одна колонка до 768px, две до
992px, три дальше. Зазор 10px по обеим осям.

### Правая панель

Правая панель появляется там, где у страницы есть постоянный контекст: расчёт
стоимости в форме создания, сводка инстанса на его странице. Она не
прокручивается вместе с контентом и на узких экранах превращается в выдвижную.
Если постоянного контекста нет, панель не показываем: пустая колонка съедает
ширину контента.

Колонка прижата к правому краю окна и отделена от контента границей. Её ширина
совпадает с навигацией: 256px, от точки `wide` 280px. Расчёт находится в
компактной карточке с полем 4px от краёв колонки. Серая подложка карточки
обрамляет переключатель периода и белый блок со строками расчёта. Наполняет
колонку страница, поэтому пустая колонка ширину не занимает.

### Прокрутка

Длинные списки заворачиваются в `ScrollArea` с тонкой полосой 4px и
градиентными тенями у краёв, которые показывают, что содержимое продолжается.

## Движение

Длительности 150–300ms, ориентир 200ms с кривой `ease`. Уход быстрее прихода:
закрытие панели или модального окна примерно на треть быстрее открытия.

Движение объясняет, откуда взялся элемент: выдвижная панель приезжает с той
стороны, где живёт её кнопка, список раскрывается от поля. Если анимация не
отвечает на вопрос «откуда это взялось», её лучше убрать.

Анимируем `transform` и `opacity`. Анимация `width`, `height`, `top` и `left`
пересчитывает раскладку на каждом кадре.

Нажатие кнопки отзывается сразу (класс `mantine-active`), результат может
прийти позже с индикатором загрузки. Ноль анимации на нажатие ощущается как
неработающая кнопка.

`prefers-reduced-motion` уважается глобально в `src/app/styles/index.css`:
анимации и переходы сводятся к мгновенной смене состояния.

Скелетоны вместо спиннеров там, где известна форма контента: это убирает скачок
раскладки в момент прихода данных.

## Компоненты

### Кнопки

Вариант выбирается по весу действия на экране, а не по тому, как хочется
покрасить. Имена вариантов лежат в `src/shared/config/variants.ts`.

| Вариант | Вес действия | Заливка / наведение / текст / граница |
|---|---|---|
| `h3_accent` | главное действие страницы, одно на экран | `--h3-variant-accent` / `--h3-variant-accent-hover` / `h3_text_inverse` / прозрачная |
| `h3_secondary` | частое второстепенное действие | `h3_bg_2` / `h3_bg_3` / `h3_text` / прозрачная |
| `h3_stroke` | действие рядом с полем, которому нужна видимая граница | прозрачная / `h3_bg_2` / `h3_text` / `h3_border_control` |
| `h3_ghost` | действие без веса: иконки в панелях, пункты меню | прозрачная / `h3_bg_2` / `h3_text` / прозрачная |

Размеры берутся из шкалы Mantine. Иконочные кнопки (`ActionIcon`) рядом с
полем берут размер `input-md` или `input-sm`, чтобы совпасть с ним по высоте;
в панелях используется `md`.

Иконки Lucide, штрих 1.5, размер 16px, `currentColor`. Эмодзи вместо иконок не
используем. Зазор между иконкой и текстом 8px.

Состояния: наведение меняет заливку на `hover`-токен варианта; нажатие даёт
лёгкое сжатие; фокус с клавиатуры показывает кольцо фокуса, и снимать его через
`outline: none` нельзя ни при каких условиях; загрузка показывает индикатор
внутри кнопки и блокирует её; заблокированная кнопка использует `h3_disabled`
для фона, `h3_disabled_color` для текста и курсор `not-allowed`.

Иконочная кнопка без подписи обязана иметь `aria-label`. После нажатия на
кнопку, запускающую операцию, показываем состояние: индикатор в кнопке, потом
уведомление об успехе или ошибке. Минимальная область нажатия на сенсорных
экранах 44×44px: иконочным кнопкам размера `md` нужен либо больший размер, либо
расширенная область через псевдоэлемент.

### Поля и элементы управления

Поля используют вариант `default` и размер `md` в основной форме, `sm` для
второстепенных полей. Граница `1px solid h3_border_control`, радиус `h3_sm`,
плейсхолдер `h3_text_1`, в фокусе граница `h3_border_focus`. Эти переменные
задаёт `src/app/styles/mantine.css`.

Плейсхолдер показывает пример значения (`valkey-1474`), а не название поля.
Название всегда стоит отдельной видимой подписью.

Поле может иметь секцию слева или справа: иконку, кнопку, единицу измерения.
Если секция некликабельна, её события отключаются, чтобы клик попадал в поле.

Числовое поле показывает значение вместе с единицей прямо в тексте: `2 ГБ`.
Справа две кнопки `h3_secondary` с иконками минуса и плюса и `aria-label`
«Уменьшить» и «Увеличить». Ввод с клавиатуры остаётся доступным
(`inputmode="decimal"`).

Выпадающий список: правая секция с шевроном, поле только для чтения с курсором
`pointer`, роль `combobox`, список `listbox`, выбранный элемент помечен галочкой
и `aria-selected`. Максимальная высота списка 220px, дальше прокрутка.

Радиогруппа карточками: выбранная карточка получает границу
`h3_border_accent` и тень `h3_primary`, а радио внутри неё получает заливку
`h3_bg_accent` и точку `h3_mint-8`. Состояние передаётся и цветом, и формой,
поэтому не теряется при дальтонизме.

Слайдер для дискретных ступеней с подписями (например размеры инстанса).
Размер `xl` и радиус `h3_md`: дорожка 12px, ручка квадратная со скруглением,
24px. Заполненная часть `h3_border_accent`, ползунок `h3_bg_accent`.
Подписи ступеней всегда видимы под дорожкой: цвет ползунка на белом даёт
1.71:1, и полагаться на него как на единственный признак положения нельзя.
Если значений больше десятка или шаг непредсказуемый, лучше числовое поле.

Переключатель с подписью справа: «Вкл» / «Выкл» текстом, а не только цветом.

Общие правила: у каждого поля видимая подпись; ошибка стоит под своим полем
вместе со значком, а не сводкой сверху; проверка происходит на потере фокуса,
а не только на отправке; подсказка под иконкой `info` нужна там, где название
параметра не самоочевидно; форма создания открывается с рабочими значениями по
умолчанию, и кнопку можно нажать сразу.

### Навигация

Пункт навигации (`NavLink`): заливка прозрачная, текст `h3_text`, наведение
`h3_bg_3`, текущий раздел `h3_bg_2`. Заливки наведения и текущего раздела
различаются, обе нейтральные: мятная подсветка `h3_bg_accent_1` оставлена блокам
на странице, в списке разделов она спорит с зелёным акцентом кнопок. Иконка
Lucide 16px стоит слева, шеврон справа у раскрывающихся пунктов.

Размеры строки навигации: минимальная высота 36px, внутренние отступы 8px
сверху и снизу и 12px по бокам, кегль подписи `h3_sm`, зазор между иконкой и
подписью 8px. Углы строки прямые: скругление здесь отрывает строку от края
колонки, к которому она примыкает. По бокам колонка отступа не имеет, строка занимает
её ширину целиком и подсветка доходит до края. Сверху колонка отбита на 8px,
снизу отступа нет. Логотип стоит на 13px от левого края и на 16px от верхнего
вместе с отступом колонки, снизу отбит на `h3_xl`. Значения замерены по
оригиналу консоли, поэтому 13px выпадает из шкалы отступов.
Вложенность передаётся отступом слева: 0, 20px, 40px. На третьем уровне вместо
смысловой иконки стоит точка.

Раскрывающийся пункт разделён на две зоны: ссылка ведёт в раздел, отдельная
иконочная кнопка справа с `aria-expanded` сворачивает поддерево. Так клик по
названию не превращается в случайное сворачивание.

Нижний блок навигации прижат к низу и отделён от списка разделов пустотой, без
линии: разделитель здесь спорит с границей самой колонки.

Строки блока идут вплотную, без зазора между ними. Строка с почтой повторяет
габарит строки навигации: высота 36px, отступы 8px и 12px, прямые углы,
наведение `h3_bg_3`,
длинный адрес обрезается многоточием. Нажатие на неё открывает меню с выходом,
ширина меню равна ширине строки, тень `h3_default`. Отдельной кнопки выхода во
всю ширину нет: она занимала место постоянно ради редкого действия.

Ряд иконочных кнопок `h3_ghost` стоит ниже: высота ряда 40px, внутренние
отступы 6px сверху и снизу и 8px по бокам, кнопки размера `md` (28px) с
иконками 16px, зазор 8px. Отключённая кнопка остаётся прозрачной, иначе заливка
Mantine читается как нажатое состояние.

Боковой отступ содержимого страницы 24px: столько же отделяет колонку навигации
от текста. Значение задано умолчанием `Container` в теме, отдельным страницам
его переопределять не нужно.

Хлебные крошки: кегль `h3_sm` начертания 500, разделитель `/` с отступом 8px,
максимальная ширина элемента 200px с многоточием, ссылка цвета `h3_text` с
подчёркиванием при наведении, последний элемент обычный текст.

Сегментированный контрол годится для 2–4 взаимоисключающих режимов просмотра
(период расчёта, окно метрик). Реализован радиогруппой и работает стрелками.
Для выбора значения в форме используем радио или список.

Правила: кнопка браузера «назад» возвращает туда, откуда пришли, модальные окна
и панели не ломают историю; активный раздел выделен, крошки подтверждают путь;
каждый экран адресуем прямой ссылкой (инстанс, вкладка внутри инстанса);
клавиатурному пользователю нужна первая по табуляции ссылка «пропустить
навигацию».

### Обратная связь и состояния

Уведомления показываются в верхнем правом углу, ширина контейнера 440px.
Запущенная операция показывает уведомление с индикатором, которое не
закрывается само. Успех показывает короткое уведомление, которое закрывается
через несколько секунд. Ошибка показывает причину и действие и не закрывается
сама. «Не удалось создать инстанс» без причины бесполезно: нужна причина
(исчерпана квота, имя занято) и способ это исправить.

Уведомления не заменяют состояние на странице. Если инстанс перешёл в
состояние «создаётся», это видно в списке, а не только во всплывшей плашке.

Модальное окно: по центру с отступом сверху 5dvh, радиус `h3_xl`. Используется
для подтверждения необратимых действий и коротких форм. Длинной форме нужен
свой адрес. Подтверждение удаления называет объект точно: «Удалить инстанс
`valkey-1474`?», кнопка называет действие («Удалить»), а не отвечает на вопрос.

Выдвижная панель приезжает с той стороны, где стоит вызвавшая её кнопка,
закрывается по `Esc` и клику по подложке. Фокус заперт внутри панели, после
закрытия возвращается на кнопку.

Загрузка: скелетон заголовка и центрированный лоадер под ним с запасом 120px
снизу. Место под контент резервируется всегда: появление данных не должно
сдвигать то, на что пользователь уже нацелился курсором.

Пустой список инстансов это точка входа, а не ошибка: название того, чего нет,
одно предложение о том, зачем это нужно, и кнопка создания.

Ошибки страницы разведены на три случая: страницы нет («Страница не найдена»,
«Проверьте адрес или вернитесь к списку инстансов», ссылка назад), инстанс не
найден (то же плюс кнопка возврата к списку) и сбой загрузки (сообщение и
возможность повторить). Границы ошибок стоят на нескольких уровнях, чтобы сбой
одного блока не уносил весь экран.

Правила: каждое действие получает отклик; смысл не передаётся одним цветом;
разрушительное действие подтверждается с названием объекта; сообщение говорит
на языке пользователя, а код ответа и трассировка прячутся в раскрывающийся
блок.

## Паттерны

### Страница консоли

Контейнер контента фиксирован на 784px и центрируется. 784px это колонка
контента: боковые поля 24px прибавляются к ней, а не съедаются из неё, поэтому
внешняя ширина контейнера 832px. Ширина не растягивается
под окно намеренно: форма шире примерно 800px читается хуже, глаз теряет связь
между подписью слева и полем справа. Для широких таблиц тот же контейнер
используется в режиме `fluid`.

`h1` размера `headline_sm`, без надзаголовка и описания под ним: путь
пользователь читает в крошках, объяснения живут в подсказках у полей.

Каждая страница обязана уметь четыре состояния, и все четыре проектируются
заранее: загрузка, пусто, данные, ошибка (отдельно «не найдено» с путём назад и
«сбой загрузки» с повтором).

Инстансы получают генерируемое имя вида `valkey-1474` с кнопкой перегенерации
рядом. Пользователь может переименовать, но не обязан. Формат имени: строчные
латинские буквы, цифры и дефис.

Адрес инстанса собирается отдельно, из префикса и шести случайных символов, и
после создания не меняется. В форме создания рядом с полем префикса виден
будущий адрес целиком, вместе с доменом. Адрес это копируемое техническое
значение, поэтому набирается моноширинным шрифтом.

### Форма создания инстанса

Эталон паттерна: форма создания инстанса Valkey. Поля идут от того, что
определяет остальное, к тому, что настраивается в последнюю очередь: режим,
затем готовая конфигурация с ценой, затем имя и доступ. Предупреждение об
отсутствии persistence стоит рядом с полем, к которому относится, а не сводкой
сверху.

```
h1  Новая Valkey база

Режим ⓘ
┌────────────────┐ ┌────────────────┐
│ ● Одна нода    │ │ ○ Отказоустойч.│      ← полная ширина
└────────────────┘ └────────────────┘

Конфигурация ⓘ
┌────────────────┐ ┌────────────────┐
│ ● 1 vCPU       │ │ ○ 1 vCPU       │
│   1 ГБ RAM     │ │   2 ГБ RAM     │
│   1 260 ₽/мес. │ │   1 620 ₽/мес. │
└────────────────┘ └────────────────┘

Имя ⓘ            [ valkey-1474                ] [⟳]

Белый список ⓘ   [ Выкл ] Ограничить доступ по IP

                  [    Создать инстанс         ]
```

Правила паттерна:

- форма открывается рабочей: все поля заполнены значениями по умолчанию,
  кнопку можно нажать сразу;
- слева подпись `h3_md`, справа контрол на всю ширину колонки;
- полноширинные поля (карточки выбора) выносятся наверх с подписью над ними;
- vCPU и RAM выбираются одной из готовых конфигураций; каждая карточка сразу
  показывает ресурсы, месячную цену и нехватку квоты, если она есть;
- стоимость считается на лету: правая панель показывает разбор по позициям и
  итог в выбранном периоде, каждое изменение формы немедленно отражается в
  сумме. Цена часть конфигурации, а не сюрприз после подтверждения;
- кнопка называет результат: «Создать инстанс», а не «Отправить».

Панель расчёта: сегментированный контрол периода (месяц, день, час), список
строк «параметр и цена», итог более крупным кеглем с периодом словами и иконка с
пояснением, что входит в сумму. Позиции называются так же, как поля формы.

Чего избегать: мастера с шагами (форма помещается на один экран, а шаги мешают
вернуться и поменять параметр, увидев цену); скрытых расширенных настроек, без
которых форма не работает (всё, что влияет на цену, видно сразу);
подтверждения после нажатия кнопки (пользователь уже видел конфигурацию и
сумму, подтверждение нужно на удалении, а не на создании).

## Текст

Заголовки страниц и подписи полей набираются обычным регистром: «Новый
инстанс», «Имя инстанса». Строчные заголовки целиком это интонация
маркетингового сайта, в консоли они читались бы как небрежность. Title Case
не используется нигде.

Консоль обращается на «вы»: «Выберите размер», «Проверьте адрес или вернитесь
к списку инстансов». Смешивать регистры внутри одной поверхности нельзя.

Основной термин русский, английский оригинал идёт следом в скобках при первом
употреблении: «управляемая база данных (Managed Valkey)». Аббревиатуры, которых
нет в обиходе у неспециалиста, разворачиваются. Транслитерация английских слов
при живом русском эквиваленте не используется; исключение — имена объектов
интерфейса и API («Инстансы»), там читателю есть где посмотреть, что это.
Технические имена остаются как в коде: `valkey-1474`, `rediss://`, `vCPU`,
`RAM`.

Числа, деньги, единицы: внутри каждого числа неразрывные пробелы.

| Что | Формат | Пример |
|---|---|---|
| Цена в расчёте | пробел в разрядах, запятая в дробной части | `1 926,00 ₽` |
| Цена за период | через косую черту | `545 ₽/мес` |
| Объём памяти | число, пробел, единица кириллицей | `2 ГБ` |
| Ядра | число, пробел, `vCPU` | `1 vCPU` |
| Период в итоге | словами | `1 926,00 ₽ в месяц` |

Все суммы на одном экране в одном, русском, формате. Два формата денег рядом
(`3,844.12` и `1 926,00`) сбивают: первое читается русским глазом как три с
половиной тысячных.

Кнопка называет результат, а не действие над формой: «Создать инстанс», а не
«Отправить»; «Удалить инстанс», а не «Да».

Сообщение об ошибке говорит, что случилось и что с этим делать. Технические
подробности (код ответа, идентификатор запроса) прячутся под раскрывающийся
блок: они нужны поддержке, но выкидывать их нельзя.

Избегаем превосходных степеней без числа и обещаний, которых нет в договоре:
всё, что касается доступности, ссылается на соглашение об уровне обслуживания.

## Контраст

Пороги: 4.5:1 для основного текста, 3:1 для крупного текста (от 18.66px
полужирного или 24px обычного), 3:1 для границ и графических элементов,
несущих смысл (критерий 1.4.11 Non-text Contrast). Значения посчитаны по
формуле относительной яркости WCAG 2.x для рабочих значений `tokens.css`.

  использует контрастный `h3_border_focus`, поэтому активное поле видно без
  опоры на слабую постоянную рамку;
- мятные графические элементы (`h3_border_accent`) не могут быть единственным
  признаком состояния: подписи ступеней слайдера и радио внутри карточки
  обязательны. Если понадобится состояние, видимое только цветом рамки, в
  светлой схеме берём `h3_mint-6`.

Пересчитать пары можно любым калькулятором относительной яркости WCAG; формула
стандартная, значения токенов в `tokens.css`.

## Отличия от исходного снимка

Исходный снимок темы консоли h3llo.cloud перенесён с тремя изменениями,
которых потребовал аудит контраста:

1. Светлое значение `h3_text_accent` изменено с `#51BA81` (2.42:1 на белом)
   на `h3_mint-7` `#1C7946` (5.42:1). Тёмное значение `#51BA81` сохранено:
   там 7.13:1. Токен разведён по схемам, как и остальные семантические.
2. Добавлен токен `h3_border_focus` для границы поля в фокусе: `h3_mint-6`
   `#379A64` в светлой схеме и `#6CDB9F` в тёмной. В снимке фокус использовал
   первичную мяту `#86FCBC`, которая на белом даёт 1.4:1.
3. Правило употребления `h3_text_1` и `h3_text_2` закреплено в разделе
   «Контраст».

Отличия, не связанные с контрастом:

- шрифты подключены из пакетов `@fontsource-variable/manrope` и
  `@fontsource-variable/roboto-mono`, поэтому имена семейств `Manrope Variable`
  и `Roboto Mono Variable` вместо самохостящихся `manrope` и `robotoMono`;
- семантические цвета Mantine ссылаются на переменные `--h3-*` напрямую, а не
  хранят собственные пары значений через `virtualColor`. Значение каждого
  токена существует в одном месте;
- точка изменения раскладки `1280` названа `aside`, потому что имя должно
  описывать намерение;
- цвет ссылок Mantine (`--mantine-color-anchor`) переведён на `h3_text_accent`
  вместо `h3_mint-4`, который на белом давал 1.71:1;
- высота кнопки размера `md` соответствует стандарту Mantine 36px. В исходном
  продукте главная кнопка формы была высотой 42px; если это понадобится,
  размер задаётся через `Button.extend` в теме, а не в разметке.

Материалы исходного каталога `design`, относящиеся к маркетинговому сайту
h3llo.cloud (лендинг, брендовые переменные Tailwind, регистр строчных
заголовков, обращение на «ты»), в консоль не переносились.

## Чеклист перед сдачей экрана

Проверяется на светлой и тёмной схеме, на ширинах 375, 768, 1024 и 1440px.

Токены:

- [ ] в компоненте нет hex-значений, только семантические токены `h3_*`;
- [ ] примитивы палитры не использованы напрямую, кроме обоснованных случаев;
- [ ] отступы взяты из шкалы `h3_xs`…`h3_xl`, произвольные числа только в
      макете страницы;
- [ ] радиус из шкалы, по умолчанию `h3_sm`;
- [ ] тень только у всплывающих слоёв, иерархия строится поверхностями.

Тёмная схема:

- [ ] экран проверен переключателем темы, а не только в светлой;
- [ ] главная кнопка через вариант `h3_accent`;
- [ ] нет белых пятен: плотные светлые заливки заменены полупрозрачными;
- [ ] границы читаются на тёмном фоне.

Контраст и доступность:

- [ ] основной текст даёт 4.5:1, посчитан, а не оценён на глаз;
- [ ] вторичный текст ведётся через `h3_text_2`, а не `h3_text_1`;
- [ ] границы интерактивных контролов через `h3_border_control` или контрол
      читается по заливке;
- [ ] смысл не передаётся одним цветом: есть иконка, форма или подпись;
- [ ] у каждого поля видимая подпись;
- [ ] у иконочных кнопок есть `aria-label`;
- [ ] кольцо фокуса видно и нигде не снято через `outline: none`;
- [ ] порядок табуляции совпадает с визуальным;
- [ ] есть ссылка «пропустить навигацию» на страницах с длинным меню;
- [ ] область нажатия на сенсорном экране не меньше 44×44px.

Формы:

- [ ] форма открывается с рабочими значениями по умолчанию;
- [ ] проверка происходит на потере фокуса, а не только на отправке;
- [ ] ошибка стоит у своего поля и сопровождается значком;
- [ ] кнопка называет результат;
- [ ] после нажатия видно состояние: индикатор, потом успех или ошибка;
- [ ] стоимость (если есть) пересчитывается на каждое изменение.

Состояния экрана:

- [ ] загрузка: скелетон или лоадер, место под контент зарезервировано;
- [ ] пусто: объяснение и кнопка создания;
- [ ] ошибка: причина и выход;
- [ ] не найдено: путь назад.

Движение:

- [ ] длительности в диапазоне 150–300ms;
- [ ] закрытие быстрее открытия;
- [ ] анимируются `transform` и `opacity`, а не `width` и `height`;
- [ ] бесконечные анимации останавливаются при `prefers-reduced-motion`.

Раскладка:

- [ ] нет горизонтальной прокрутки ни на одной ширине;
- [ ] ширина контента 784px, если это не таблица;
- [ ] боковые панели сворачиваются ниже 1024px;
- [ ] масштабирование страницы не заблокировано.

Иконки и графика:

- [ ] иконки Lucide, 16px, штрих 1.5, `currentColor`;
- [ ] эмодзи вместо иконок не используются;
- [ ] у декоративных иконок `aria-hidden="true"`;
- [ ] изображения в WebP или AVIF, с отложенной загрузкой и заданными
      размерами.

Текст:

- [ ] заголовки обычным регистром, обращение на «вы»;
- [ ] числа и деньги в русском формате с неразрывными пробелами;
- [ ] термин русский, английский оригинал в скобках при первом употреблении.

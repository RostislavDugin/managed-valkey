# AGENTS.md

## Обязательный скилл: humanizer

Скилл `humanizer` должен быть загружен в контекст **всегда**, без исключений:

- при **любом** запросе пользователя, независимо от темы и формулировки;
- перед **любым** действием: написание и правка кода, документации,
  комментариев, коммитов, ответов в чате, файлов любого формата;
- в **каждом** новом окне контекста и после каждого сжатия контекста;
- для **всех** субагентов и воркфлоу, которые запускаются из этого проекта.

Правило действует на первом же шаге работы: сначала вызывается скилл
`humanizer`, и только потом выполняется сам запрос. Если скилл по какой-то
причине не загрузился, работа не начинается, пока он не будет загружен.

Скилл лежит в `.skills/humanizer/SKILL.md`.

Все тексты, которые агент создаёт или редактирует, проходят через правила
этого скилла: без канцелярита, без штампов ИИ-письма, без лишних тире,
«правила трёх», расплывчатых ссылок на источники и пустых вводных фраз.

## Хранение проектных навыков

Единственное место, где лежат файлы проектных навыков, это корневой каталог
`.skills/<skill-name>`. Каталоги `.agents/skills/<skill-name>` (Codex) и
`.claude/skills/<skill-name>` (Claude) содержат только относительные
символические ссылки вида `../../.skills/<skill-name>`. Рабочая среда обязана
поддерживать символические ссылки; без них навыки не загрузятся.

Правила:

- Новый общий навык сохраняется в `.skills`, после чего в обоих каталогах
  агентов создаются относительные ссылки на него.
- Файлы навыка редактируются только по пути `.skills/...`. Создавать обычный
  каталог или копию навыка в `.agents/skills` или `.claude/skills` нельзя.
- Внешние навыки (FSD, Mantine) копируются целиком с фиксированной ревизии,
  а источник и ревизия записываются в `.skills/SOURCES.md`.
- Если `openspec update` или другой генератор заменил ссылку обычным каталогом,
  различия между копиями для Codex и Claude нужно снова объединить в `.skills`
  (когда синтаксис вызова различается, инструкция называет оба варианта:
  `$openspec-apply-change` для Codex и `/opsx:apply` для Claude), а затем
  восстановить ссылки. Команды в `.claude/commands/opsx` остаются на месте.

## Git: ветки и коммиты

Пока проект на стадии MVP, всё коммитим напрямую в `main`, без веток.
Позже перейдём на git flow: `main` для релизов, `develop` как основная ветка
разработки, от неё `feature/*` и `release/*`, от `main` идут `hotfix/*`.

Сообщения коммитов пишем по Conventional Commits: `type(scope): описание`.
Типы: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `build`, `ci`,
`perf`, `style`, `revert`. Ломающие изменения помечаем `!` перед двоеточием.

Сообщение короткое: одна строка заголовка, при необходимости пара строк тела.
Простыни текста, пересказ диффа и списки всех тронутых файлов не пишем.
Строки в сообщении не переносим по ширине 80 символов: абзац идёт одной
строкой, перенос делаем только там, где он нужен по смыслу.

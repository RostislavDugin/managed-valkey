# AGENTS.md (api)

Инструкции для работы в каталоге `api`. Читать в таком порядке:

1. [../AGENTS.md](../AGENTS.md) — общие правила проекта, включая обязательный
   навык `humanizer`, правило хранения навыков в `../.skills` и проверки
   pre-commit.
2. [../SYSTEM.md](../SYSTEM.md) — разделы 3 (границы и права), 4 (данные и
   миграции), 5 (HTTP API), 10 (аутентификация), 11 (логи), 13 (окружения) и
   14 (тесты).

## Ответственность

API владеет HTTP, авторизацией, PostgreSQL и фоновой синхронизацией с
Kubernetes. Управление подами Valkey ему не принадлежит: намерение уходит в
`spec` CR, наблюдения читаются из `status`.

HTTP-обработчики не вызывают Kubernetes. Фоновые циклы используют отдельный
клиент и повторяют неудачные операции, поэтому недоступный control plane не
делает API неготовым.

Пакет `../operator/api/v1alpha1` доступен как публичный контракт CRD. Другие
пакеты оператора импортировать нельзя.

## Стек

Go из `../go.mod`, Gin, GORM с драйвером PostgreSQL, `goose` для схемы,
`slog` через общий `../internal/logging`. Инструменты запускаются через
`go tool`, отдельная установка не нужна.

## Команды

| Команда | Что делает |
|---|---|
| `just run` | применяет миграции и запускает API на хосте |
| `just format` | форматирует API и общий Go-код, затем добавляет эту область в индекс Git |
| `just lint` | проверяет API и общий код линтером, сборкой и `go mod tidy -diff` |
| `just test` | готовит отдельную базу и запускает все тесты без k3s |
| `just test-full` | добавляет однонодовый k3s и тесты Kubernetes-синхронизации |
| `just migration-generate <name>` | создаёт SQL-миграцию с временным префиксом |
| `just migration-up` | применяет ожидающие миграции к `DATABASE_URL` |
| `just migration-down` | откатывает последнюю применённую миграцию |

Перед завершением задачи выполняй `just format`, `just lint` и `just test`.
Команда тестов сама запускает общий локальный PostgreSQL и удаляет только базу
своего запуска. `just test-full` нужен после изменений Kubernetes-синхронизации
или тестовой обвязки k3s, но не заменяет быстрый набор. `just format` добавляет
изменения `api` и общего `internal` в индекс, поэтому сначала проверь, что другой
агент не меняет эти файлы.

## Структура

```
api/
  cmd/api/            точка входа
  internal/
    api/              gin-обработчики, middleware, проверки состояния
    config/           разбор обязательной конфигурации из env
    store/            подключение GORM и репозитории PostgreSQL
```

Новый предметный код добавляется по разделу 16 `SYSTEM.md`: `apierr`, `auth`,
`domain`, `billing`, `audit`, `opslog`, `sync`, `web`.

## Оформление кода

Разбивай код пустыми строками на логические блоки: импорты разных источников,
объявления, подготовку данных, основную работу и возврат. Комментарий пишется
о неочевидной причине решения, а не о том, что делает следующая строка.

Используй возможности той версии Go, которая закреплена в `../go.mod`:
`errors.Is` и `errors.Join`, `slog`, `context.WithoutCancel`, обобщённые
функции стандартной библиотеки вместо самописных помощников.

Ошибка оборачивается с описанием операции: `fmt.Errorf("подключиться к
PostgreSQL: %w", err)`. Типизированные ошибки объявляются переменными или
типами, чтобы вызывающий проверял их через `errors.Is` и `errors.As`.

## Время

Всё время в UTC. Значения приложения создаются как `time.Now().UTC()`, в базе
хранятся в `TIMESTAMPTZ`. Часовой пояс выбирается только при показе
пользователю.

Зависимости от времени изолируются интерфейсом `Clock`, чтобы тест не ждал
реальные интервалы.

## Логи

Один общий `slog.Logger` создаётся в `../internal/logging` и передаётся дальше
явно. Сообщение начинается со строчной буквы и не заканчивается точкой; ключи
атрибутов пишутся в `snake_case`; ошибка кладётся в атрибут `error`.

Известные идентификаторы добавляются один раз на границе операции через
`logger.With`. Для запроса это `request_id` и `user_id`.

Размеры, счётчики и переходы состояния остаются отдельными атрибутами, а не
собираются в текст через `fmt.Sprintf`: VictoriaLogs фильтрует их по полям.

Пароли, хеши, тела запросов авторизации, создания и смены пароля, заголовки
`Authorization` и содержимое Secret не логируются ни на одном уровне.

## PostgreSQL

Схему меняют только миграции `goose` из `../migrations`. `AutoMigrate` GORM и
изменение схемы из кода приложения запрещены.

Каждая GORM-модель, которая соответствует таблице, объявляется в
отдельном файле `internal/store`. В одном файле нельзя объявлять
модели нескольких таблиц. Структуры для входных данных и результатов
запросов, которые не отображают таблицу, можно хранить рядом с запросами,
которые их используют.
У каждого поля GORM-модели явно указывай `gorm`-тег с именем колонки.

Правила SQL: первичные ключи UUIDv7 через встроенную `uuidv7()` PostgreSQL 18,
время в `TIMESTAMPTZ`, булевы колонки с префиксом `is_` или `has_`, таблицы
предметной области с префиксом `valkey_` кроме общих таблиц аккаунтов.

Таблица создаётся до внешних ключей и вторичных индексов. Каждый внешний ключ
и индекс объявляется отдельно и с явным именем. Перед завершением задачи
проверь новые миграции по этим правилам вручную.

Миграция выполняется в транзакции. `NO TRANSACTION` допустим только для
операции PostgreSQL, которую нельзя выполнить в транзакции, с пояснением
причины в самом файле.

Production-миграции аддитивны: колонка удаляется или переименовывается только
после выкладки версии API, которая перестала её читать.

## Тесты

Юнит-тесты проверяют расчёты и переходы без инфраструктуры. Интеграционные
используют настоящую PostgreSQL: `just test` создаёт базу запуска, применяет
миграции и выполняет все проверки, которым не нужен Kubernetes. Тесты с тегом
сборки `k3s` входят только в `just test-full`; команда передаёт им отдельный
kubeconfig. Оператор и Envoy в этом кластере не запускаются, каждый тест убирает
свои данные.

Адрес тестовой базы приходит из `TEST_DATABASE_URL`. Тест, которому нужна
настоящая база, пропускается, когда переменная не задана.

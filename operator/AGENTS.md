Инструкции для работы в каталоге `operator`. Читать в таком порядке:

1. [../AGENTS.md](../AGENTS.md) — общие правила проекта, включая обязательный

   pre-commit.
2. [../SYSTEM.md](../SYSTEM.md) — разделы 3 (границы и права), 6 (оператор),
   7 (сеть и TLS), 9 (отказоустойчивость), 11 (логи), 13 (окружения) и
   14 (тесты).
3. [SCAFFOLD.md](SCAFFOLD.md) — из какого каркаса Kubebuilder получены `cmd`,
   `api/v1alpha1`, `internal/operator` и `config`.

## Ответственность

Оператор управляет объектами Kubernetes и процессами Valkey. У него нет
конфигурации PostgreSQL и адреса HTTP API сервиса: подключаться к базе или
вызывать API сервиса нельзя. Всё состояние приходит через CR
`ValkeyInstance` и уходит обратно в его `status`.

Оператор не меняет `spec`: намерение туда записывает API. Миграции схемы
PostgreSQL к его обязанностям не относятся.

Пакет `api/v1alpha1` публичный: его импортирует и API. Пакеты
`../api/internal/...` импортировать нельзя.

## Стек

Go из `../go.mod`, `controller-runtime`, `controller-gen` для DeepCopy, CRD и
RBAC, `envtest` для тестов Kubernetes API, `slog` через общий
`../internal/logging`. Инструменты запускаются через `go tool`.

## Команды

| Команда | Что делает |
|---|---|
| `just run` | запускает оператор на хосте с kubeconfig из `../tmp/k3s/dev` |
| `just format` | форматирует оператор и общий Go-код, затем добавляет эту область в индекс Git |
| `just lint` | проверяет оператор, общий код, сборку, зависимости и сгенерированные ресурсы |
| `just test` | запускает unit/envtest без k3s |
| `just test-full` | добавляет сценарии `single`, `ha`, изменений и отказов на отдельных k3s |

Перед завершением задачи выполняй `just format`, `just lint` и `just test`.
`just test-full` нужен после изменений поведения оператора или его k3s-обвязки.
`just format` добавляет изменения `operator` и общего `internal` в индекс,
поэтому сначала проверь, что другой агент не меняет эти файлы.
`just run` требует dev-кластер, подготовленный командой
`../scripts/k3s_bootstrap.sh`.

Интеграционным тестам нужен беспарольный `sudo` для `ip route replace` и
`ip route del`: хостовый manager подключается к адресам Pod через маршруты
выделенного k3s-стенда, а очистка удаляет только записанные стендом маршруты.

## Структура

```
operator/
  cmd/operator/         точка входа и manager
  api/v1alpha1/         типы CRD и сгенерированный DeepCopy
  internal/
    config/             разбор конфигурации из env
    operator/           reconcile и настройка manager
  config/crd/           сгенерированные CRD
  config/rbac/          сгенерированные ClusterRole и Role
```

Каталог `config` генерируется из Go-маркеров отдельной внутренней командой.
`just run`, `just test` и `just test-full` проверяют сгенерированные файлы во
временном каталоге и не меняют их. Править сгенерированные файлы руками нельзя:
изменение вносится в тип или маркер. Исключение —
`config/crd/kustomization.yaml`, который перечисляет сгенерированные файлы.

Новый предметный код добавляется по разделу 16 `SYSTEM.md`:
`internal/operator` и `internal/valkey`.

## Reconcile

Reconcile идемпотентен: повторный вызов на неизменном состоянии не создаёт
объектов и не меняет `status`. Желаемое состояние вычисляется из `spec` и
наблюдений, а не из того, какое событие пришло.

Ошибка возвращается наружу, чтобы контроллер повторил вызов с задержкой.
`ctrl.Result{RequeueAfter: ...}` используется, когда нужно дождаться внешнего
события, а не для маскировки ошибки.

`context.Context` передаётся во все вызовы Kubernetes и Valkey. Отмена
контекста означает остановку manager: длинные операции обязаны её замечать.
Отмена вызова не отзывает уже отправленную команду Valkey.

`observedGeneration` подтверждается только после применения всех полей
соответствующего `spec`. Отдельные операции подтверждаются своими полями
`status`.

При потере Lease оператор прекращает изменяющие команды, закрывает соединения
и завершает процесс.

## Оформление кода

Разбивай код пустыми строками на логические блоки: импорты разных источников,
объявления, подготовку данных, основную работу и возврат. Комментарий пишется
о неочевидной причине решения, а не о том, что делает следующая строка.

Используй возможности той версии Go, которая закреплена в `../go.mod`:
`errors.Is` и `errors.Join`, `slog`, `context.WithoutCancel`, обобщённые
функции стандартной библиотеки вместо самописных помощников.

Ошибка оборачивается с описанием операции: `fmt.Errorf("создать manager: %w",
err)`. Типизированные ошибки объявляются переменными или типами, чтобы
вызывающий проверял их через `errors.Is` и `errors.As`.

## Время

Всё время в UTC. Отметки в `status` создаются как `time.Now().UTC()`.
Зависимости от времени изолируются интерфейсом `Clock`, чтобы тест не ждал
реальные интервалы: пороги отказа и таймауты из раздела 13 `SYSTEM.md`
проверяются без реального ожидания.

## Логи

Один общий `slog.Logger` создаётся в `../internal/logging` и передаётся в
manager через адаптер `logr`. Сообщение начинается со строчной буквы и не
заканчивается точкой; ключи атрибутов пишутся в `snake_case`; ошибка кладётся
в атрибут `error`.

Идентификатор инстанса добавляется один раз на границе операции через
`logger.With` под ключом `instance_slug`.

Пароли, SHA-256 из ACL и содержимое Secret не логируются. Ошибки клиента
Valkey фильтруют аргументы `AUTH` и `ACL SETUSER`.

## Тесты

`envtest` запускает настоящий kube-apiserver без worker-нод: он проверяет CRD,
`resourceVersion` и конфликты. Файлы этого набора помечаются тегом сборки
`envtest`.

`fake`-клиент `controller-runtime` допустим для проекции строки в объекты, но
`envtest` он не заменяет.

`just test` готовит файлы envtest и выполняет unit/envtest. Команда сохраняет
журналы и явно отмечает, что полная k3s-матрица не запускалась. Задание CI
`test-operator` вызывает эту команду.

`just test-full` проверяет `single`, `ha`, переключение primary, изменение
размера, смену пароля и управляемые отказы с настоящими подами. Большинство
сценариев запускает manager внутри Go-теста. `OP-01`, `OP-02` и `ND-04`
используют собранный один раз образ оператора, разворачивают его в k3s и
воздействуют на его Pod либо Lease. Каждый сценарий из
`../scripts/operator_test_scenarios.tsv` получает независимый k3s
из 1–4 нод и одну или две реплики Envoy. Тест создаёт `ValkeyInstance` и входные
Secret напрямую через Kubernetes, без HTTP API и PostgreSQL. Сценарии, которые
ещё не реализованы, перечислены в [TODO.md](TODO.md).

Очередь по умолчанию допускает 12 сценариев, но общий бюджет 28672 MiB и
минимум 3072 MiB свободной памяти могут снизить фактическое число стендов.
Одновременно готовятся не более шести кластеров. Подготовка артефактов и быстрые
тесты резервируют 4096 MiB. Значения меняются через
`MV_OPERATOR_TEST_MAX_PARALLEL`, `MV_OPERATOR_PREPARATION_MEMORY_MIB`,
`MV_TEST_MEMORY_BUDGET_MIB`, `MV_TEST_MIN_AVAILABLE_MIB` и
`MV_TEST_MAX_PARALLEL_BOOTSTRAPS`.

Корневые e2e-тесты проходят через HTTP API. Текущий набор проверяет регистрацию
без создания Valkey; будущие сквозные сценарии будут подключаться к созданному
Valkey. Они не входят в тесты оператора.

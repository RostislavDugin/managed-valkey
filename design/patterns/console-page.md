# Страница консоли

## Каркас

```
шапка 52px                     хлебные крошки ── управление
────────────────────────────────────────────────────────────
навигация │  контейнер 784px по центру           │ правая
256/280px │                                      │ панель
          │  h1  ← 64px сверху, 48px снизу       │ (если есть
          │                                      │  живой расчёт
          │  содержимое                          │  или контекст)
          │                                      │
          │  ← запас 120px снизу                 │
```

Контейнер контента фиксирован на 784px и центрируется в оставшемся пространстве.
Ширина не растягивается под окно намеренно: форма шире примерно 800px читается хуже,
потому что глаз теряет связь между подписью слева и полем справа.

Для широких таблиц применяется тот же контейнер в режиме `fluid`: список ресурсов
занимает всю доступную ширину, потому что таблице колонок нужно больше места.

## Заголовок

`h1` размера `headline_sm` (30px), без надзаголовка и без описания под ним. Путь
пользователь читает в хлебных крошках, объяснения живут в подсказках у полей.

## Состояния экрана

Каждая страница обязана уметь четыре состояния, и все четыре проектируются заранее,
а не дописываются после.

**Загрузка.** Скелетон заголовка плюс лоадер. Раскладка уже занимает своё место,
чтобы приход данных не сдвинул страницу.

**Пусто.** Название того, чего нет, короткое объяснение, кнопка создания. Пустой
список — самая частая первая страница нового пользователя, и она должна вести дальше.

**Данные.** Основное состояние.

**Ошибка.** Отдельно «не найдено» и «сбой загрузки». У первого есть путь назад,
у второго — возможность повторить.

## Правая панель

Правая панель появляется там, где у страницы есть постоянный контекст: расчёт
стоимости в форме создания, сводка ресурса на его странице. Она не прокручивается
вместе с контентом и на узких экранах превращается в выдвижную.

Если постоянного контекста у страницы нет, панель не показываем: пустая колонка
съедает ширину контента.

## Именование ресурсов

Ресурсы получают генерируемое имя вида `virtual-machine-1474` с кнопкой перегенерации
рядом. Пользователь может переименовать, но не обязан. Это снимает решение с первого
шага: чтобы завести машину, не нужно придумывать ей название.

Формат имени: строчные латинские буквы, цифры и дефис. Такое имя без экранирования
уходит в DNS, метки Kubernetes и командную строку.

## Разделы проекта

Слева перечислены разделы одного проекта, а не всего облака. Переключение проекта
живёт над списком отдельным элементом. Иерархия «проект → ресурсы проекта» держится
последовательно: адрес страницы тоже содержит идентификатор проекта.

## Why

Пользовательские процессы Valkey сейчас работают в `StatefulSet` и зависят от контейнерного `restartPolicy: Never` через `ContainerRestartRules`. Рабочий кластер не исполняет эту настройку, а изменить конфигурацию поставщика нельзя, поэтому выпуск `production-kubernetes-delivery` остановлен.

## What Changes

- Передать создание и замену пользовательских `Pod` непосредственно оператору; задать `spec.restartPolicy: Never` самому `Pod` без `ContainerRestartRules`.
- Сохранить один процесс для `single` и три для `ha`, устойчивые имена, разнесение HA по нодам и существующие сетевые адреса.
- Сохранять идентичность и доказательства остановки процессов до удаления и замены; продолжать незавершённые операции после перезапуска оператора. Переход не ослабляет запрет двух доступных для записи основных процессов.
- Перенести изменение CPU/RAM и удаление на прямое управление `Pod`, сохранив последовательность операций, закреплённый образ и подтверждение применённого поколения.
- Убрать зависимость тестовых окружений от `ContainerRestartRules`, дополнить проверки в `operator/` и выполнить существующий полный набор оператора. Общие интеграционные и сквозные сценарии не расширять.
- **BREAKING** для обновления окружения: переход существующих пользовательских `StatefulSet` без остановки не поддерживать; перед обновлением требуется их штатное удаление прежним оператором по согласованию с владельцем окружения. Сам оператор остаётся в его `StatefulSet`; публичный API не меняется.

## Capabilities

### New Capabilities

- `operator-pod-lifecycle`: прямое владение `Pod`, сохранённая конфигурация запуска и безопасное восстановление состава без контроллера `StatefulSet` и `ContainerRestartRules`.

### Modified Capabilities

- `single-instance-lifecycle`: создание, инициализация учётных данных и удаление отдельного `Pod` вместо пользовательского `StatefulSet`.
- `operator-resource-metadata`: прямое владение `Pod` и перенос описательных метаданных без шаблона `StatefulSet`.

## Impact

Изменятся управление ресурсами и права в `operator/`, проверки оператора, подготовка локальных и тестовых кластеров, `SYSTEM.md` и `SYSTEM-DETAIL.md`. Формат HTTP API, расчёт вместимости и намерения `ValkeyInstance.spec` сохраняются. Внутренний `status` дополняется сохранённым образом для восстановления конфигурации запуска после потери всех `Pod`.

Совместимость обновления окружения ограничена: новый оператор нельзя устанавливать поверх пользовательских `StatefulSet`. Это не изменение публичного API; данные кэша при согласованном пересоздании инстансов теряются. На 11 сентября 2026 года рабочая база не содержала активных инстансов, но перед выпуском это нужно проверить снова.

После завершения этого изменения `production-kubernetes-delivery` заменяет свою предварительную проверку нод и продолжает выпуск с полным CI/CD. Настройка DNS, секреты и обновление рабочего API остаются в том изменении.

## Why

Управление Valkey пока хранит данные в браузере и имитирует готовность. Нужны постоянные инстансы в PostgreSQL и HTTP API, которое атомарно принимает изменения, резервирует квоту и сразу отклоняет создание при нехватке ресурсов кластера.

## What Changes

- Добавить создание, список, чтение, переименование, maintenance, ресайз, whitelist, credentials и смену пароля Valkey; подключить их к фронту.
- Сохранять намерение отдельно от наблюдаемого состояния. Синхронизацию с Kubernetes, операторские сценарии и k3s-тесты выполнить отдельной задачей.
- Реализовать soft delete: запрос удаления закрывает биллинг, подтверждённое удаление освобождает квоту; строка инстанса и история остаются.
- Проверять квоты и последовательность изменений под общим транзакционным advisory lock. `MANAGED_K8S_NODE_VCPU` и `MANAGED_K8S_NODE_RAM_GB` задают общий бюджет Valkey всего кластера.
- Возвращать `422 NOT_ENOUGH_RESOURCES` в исходном запросе создания при недостатке бюджета. В v1 нет ожидания добавления ресурсов или автоматического расширения кластера.
- Выделить внутренний сервис аудита с инверсией зависимостей. Сервисы пользователей и Valkey вызывают его в своей транзакции. HTTP API аудита отложить.
- Записывать биллинговые периоды при принятии создания, ресайза и удаления; расчёт месячного расхода и его HTTP API отложить.
- Добавить идемпотентность, подробный контракт ошибок и интеграционные тесты через TCP HTTP и PostgreSQL, включая конкурентность и откаты.
- **BREAKING**: заменить браузерное хранилище Valkey сервером; старые локальные базы не импортировать. Удаление и применение настроек становятся асинхронными. До появления API аудита и метрик соответствующие вкладки показывают недоступность данных без демонстрационных событий и измерений.
- Уточнить `SYSTEM.md` и `SYSTEM-DETAIL.md`: аудит, общая квота, немедленный отказ, soft delete и отложенная политика длительного хранения аудита.

## Capabilities

### New Capabilities

- `api-valkey-management`: HTTP-контракт инстансов, состояния, soft delete, идемпотентность, ошибки и транзакции.
- `api-valkey-quotas`: серверная сетка размеров, цены, резервирование ресурсов пользователя и кластера, конкурентный admission control.
- `api-audit`: внутренний сервис записи аудита для пользователей и Valkey, атомарность и сохранение истории.
- `api-billing-periods`: интервалы стоимости принятых конфигураций без расчёта месячного расхода.

### Modified Capabilities

- `api-auth`: запись аудита через сервис и реальный расход квоты в `/v1/me`.
- `web-valkey-management`: серверные данные и ограничения, состояния принятия/применения/удаления, обработка ошибок.
- `web-valkey-observability`: явная недоступность метрик и аудита до подключения их HTTP API.

## Impact

Затронуты `api/internal`, миграции PostgreSQL, `web/src/pages/valkey`, общий HTTP-клиент и получение текущей сессии, параметры окружения и тестовые помощники. Сохраняются Gin, GORM, PostgreSQL 18 и goose с `-allow-missing`. Новая инфраструктура не требуется. Код оператора, Kubernetes-клиенты, фоновые циклы и независимый change `add-ci-cd` в эту задачу не входят.

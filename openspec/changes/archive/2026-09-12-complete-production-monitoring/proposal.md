## Why

Production не показывает загрузку CPU, потому что развёртывание не устанавливает Metrics Server, хотя оператор читает CPU через `metrics.k8s.io`. Кратковременное отсутствие данных также разрывает линию графика и визуально выглядит как продолжительный отказ.

## What Changes

- Добавить Metrics Server с закреплённой версией в production-развёртывание Kubernetes.
- Считать развёртывание успешным только после готовности `metrics.k8s.io` и получения метрик рабочего Pod.
- Сохранить независимость оператора от временной недоступности CPU: ошибка Metrics Server по-прежнему не останавливает сбор показателей Valkey и управление экземплярами.
- Соединять пропуск на графиках памяти, CPU, подключений и операций, если между предыдущим и следующим фактическими измерениями прошло не больше одной минуты.
- Оставлять видимый разрыв, если между измерениями прошло больше одной минуты, у пропуска нет значения с одной из сторон либо метки времени недопустимы. Вычисленное для отрисовки значение не выдаётся за полученную метрику.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ci-cd`: production-развёртывание устанавливает Metrics Server и проверяет рабочий путь `metrics.k8s.io` до фиксации успешного выпуска.
- `web-valkey-observability`: все графики по меткам времени соединяют пропуски между измерениями длительностью не больше одной минуты, но сохраняют более долгие разрывы и не показывают вычисленное значение как измеренное.

## Impact

Изменение затронет production-сценарий Kubernetes, его автоматические проверки, закреплённую внешнюю зависимость Metrics Server, подготовку рядов мониторинга и тесты клиентского приложения. Публичный HTTP API, схема PostgreSQL, CRD `ValkeyInstance` и формат сохранённых метрик не меняются.

## Why

Полный Playwright e2e занимает в CI около 15 минут и определяет длительность всего workflow. Сценарии нельзя безопасно выполнять параллельно на одном стенде из-за общей квоты и отказов Kubernetes, но независимые группы можно запускать на отдельных GitHub runners.

## What Changes

- Разделить CI e2e на три параллельные группы: жизненные циклы, квоты и отказы.
- Поднимать для каждой группы отдельные PostgreSQL, трёхнодовый k3s, API, оператор и web.
- Сохранить последовательный запуск всех семи сценариев на одном стенде для локальных `just test-e2e` и `just test-e2e-headed`.
- Проверять полный каталог до запуска CI-матрицы и требовать успеха каждой группы в итоговом задании.
- Разделять диагностику и артефакты по имени группы.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ci-cd`: полный Playwright-набор выполняется тремя параллельными группами и собирается в один обязательный результат.
- `test-orchestration`: e2e runner поддерживает явный выбор непересекающейся группы без изменения локального последовательного запуска.

## Impact

Изменение затронет GitHub Actions workflow, команды e2e, проверку обязательного каталога, маршрутизацию Playwright-сценариев, имена диагностических артефактов и документацию тестов. Продукт, публичный HTTP API и схема PostgreSQL не меняются.

## Context

См. `proposal.md`. Все семь Playwright-сценариев сейчас выполняются одним worker на одном стенде. Теги уже разделяют штатные жизненные циклы (`@prod`), квоты (`@local`) и отказы Kubernetes (`@local-k8s`). Сценарии внутри каждой категории используют общую ёмкость или меняют состояние кластера, поэтому один стенд нельзя безопасно разделить между параллельными workers.

## Goals / Non-Goals

**Goals:**

- Сократить критический путь GitHub Actions параллельным выполнением трёх категорий.
- Сохранить один worker и один стенд внутри каждой категории.
- Оставить локальные headless и headed команды без изменений для разработчика.
- Сохранить единый обязательный результат e2e перед deploy.

**Non-Goals:**

- Не запускать несколько Playwright workers на одном k3s.
- Не менять состав семи сценариев или их проверки.
- Не выполнять production e2e автоматически.
- Не запускать три тяжёлых стенда параллельно на локальной машине.

## Decisions

### CI использует matrix одного job

`test-e2e` получает matrix из `lifecycle`, `quotas` и `failures` с `fail-fast: false`. GitHub Actions создаёт для каждой записи отдельный runner, поэтому базы, Docker Compose projects, k3s и процессы изолированы штатной обвязкой. Итоговый job продолжает зависеть от одного идентификатора `test-e2e`; его результат успешен только после успеха всех записей matrix.

Отдельные job-идентификаторы потребовали бы перечислять каждую группу в итоговом барьере и дублировать шаги workflow. Параллельные workers в одном job не подходят из-за общей квоты и отказов Kubernetes.

### Группа выбирается до подготовки стенда

Runner принимает явное имя группы и переводит его в фильтр Playwright: `lifecycle` выбирает `@prod`, `quotas` выбирает `@local`, `failures` выбирает `@local-k8s`, а локальное значение `all` не задаёт фильтр. Неизвестное имя и пустой результат завершают команду до создания k3s.

Обязательный каталог проверяется целиком при каждом запуске. Лёгкий автоматический тест дополнительно подтверждает, что три фильтра не пересекаются и вместе выбирают все семь сценариев. Так matrix не требует отдельного предварительного job, который задержал бы её запуск.

### Локальные команды сохраняют один общий стенд

`just test-e2e` и `just test-e2e-headed` передают группу `all`. Разработчик по-прежнему получает один k3s, API и оператор, а headed сохраняет трёхсекундный интервал между пользовательскими действиями. Групповой режим используется в CI и может быть вызван явно для диагностики одного набора.

### Диагностика получает имя группы

Имена опубликованных артефактов включают запись matrix. Внутри каждого runner каталог состояния уже уникален. Это исключает конфликт артефактов и позволяет сразу определить упавшую категорию.

## Risks / Trade-offs

- [Три стенда увеличивают суммарные минуты CI] → Matrix применяется только в GitHub Actions; локальный запуск остаётся одностендовым.
- [Одна группа может случайно потерять сценарий] → Проверка каталога сверяет объединение и отсутствие пересечений до bootstrap.
- [Остановка одной группы может скрыть ошибки других] → `fail-fast: false` разрешает остальным группам завершиться и сохранить диагностику.
- [Дополнительные runners могут ждать свободный слот] → Все записи matrix создаются сразу и не зависят от lint; при доступных runners они выполняются параллельно.
- [Трёхнодовый стенд может заполнить диск GitHub runner] → Перед подготовкой стенда удаляются неиспользуемые SDK, а импорт образа в containerd повторяется до трёх раз на каждой ноде. После исчерпания попыток группа завершается ошибкой и сохраняет диагностику.
- [`k3s-agent` может завершиться при первом подключении к запускающемуся API server] → Контейнер перезапускается после штатного выхода, `k3s_bootstrap.sh` дожидается готовности Node, а образ Valkey загружается после подготовки кластера. Загрузчик образа восстанавливает остановившийся контейнер перед повтором импорта.
- [Перенос primary на worker-ноду может временно закрыть прежний адрес до внесения проверяемого отказа] → Сценарий ждёт возвращения HA в `running` после переноса и только затем запускает фоновые пробы.

## Migration Plan

После обновления runner и его тестов workflow переводится на matrix. Откат возвращает одно задание `test-e2e` без имени группы; локальные команды и формат сценариев при этом не меняются.

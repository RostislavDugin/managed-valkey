## ADDED Requirements

### Requirement: API доставляет метаданные владельца

Для каждого активного инстанса API SHALL поддерживать на `Namespace` и `ValkeyInstance` метки `valkey.h3llo-demo.com/instance`, `valkey.h3llo-demo.com/instance-id`, `valkey.h3llo-demo.com/user-id` и аннотацию `valkey.h3llo-demo.com/user-email`. Значения SHALL соответствовать `slug`, ID инстанса, ID пользователя и сохранённому снимку email. Email MUST NOT записываться в метку. API SHALL сначала проверить существующие признаки принадлежности и UID, затем восстановить только управляемую аннотацию, сохранив `status`, посторонние метки, аннотации и `finalizers`.

#### Scenario: Первоначальная доставка

- **WHEN** цикл доставки создаёт объекты нового инстанса
- **THEN** его `Namespace` и `ValkeyInstance` содержат ID инстанса, ID пользователя и точный email владельца в установленных полях `metadata`

#### Scenario: Дополнение существующего инстанса

- **WHEN** принадлежащие инстансу `Namespace` и `ValkeyInstance` имеют правильные ID и UID, но email-аннотация отсутствует или отличается от снимка PostgreSQL
- **THEN** API исправляет управляемую аннотацию без требования ручного восстановления
- **AND** не меняет наблюдения оператора или посторонние метаданные

#### Scenario: Повреждена идентичность объекта

- **WHEN** ID, `slug` или сохранённый UID найденного объекта не соответствует строке PostgreSQL
- **THEN** API не исправляет email и оставляет объект для ручного разбора по действующему протоколу восстановления

#### Scenario: Метаданные уже совпадают

- **WHEN** управляемые метки и email-аннотация содержат ожидаемые значения
- **THEN** повторный проход не записывает объект и не меняет его `resourceVersion`

## ADDED Requirements

### Requirement: Инстанс хранит снимок email владельца

Каждая строка `valkey_instances` SHALL содержать непустой нормализованный `user_email`, соответствующий владельцу в момент создания инстанса. Создание SHALL сохранять `user_id` и `user_email` в той же транзакции, что инстанс, аудит, биллинговый период и идемпотентный ответ. Публичные мутации MUST NOT менять снимок или возвращать его в HTTP DTO. Миграция SHALL заполнить снимок для всех существующих строк, включая удалённые, из связанного аккаунта и SHALL сохранять успешное создание инстансов работающей предыдущей версией API во время выкладки.

#### Scenario: Новый инстанс

- **WHEN** аутентифицированный пользователь создаёт инстанс
- **THEN** строка инстанса получает его нормализованный email вместе с `user_id`
- **AND** последующие изменения конфигурации и удаление не меняют снимок

#### Scenario: Обновление существующей базы

- **WHEN** миграция применяется к базе с активными и удалёнными инстансами
- **THEN** каждая существующая строка получает email связанного пользователя без изменения остальных данных

#### Scenario: Создание во время выкладки

- **WHEN** после применения миграции предыдущая версия API создаёт инстанс только с `user_id`
- **THEN** база сохраняет снимок email и создание завершается по прежнему контракту

## MODIFIED Requirements

### Requirement: Команды запуска и проверки оператора

Каталог `operator` SHALL содержать `Justfile` с публичными командами `test` и `run`. Единая команда `test` SHALL выполнять unit-тесты, envtest и медленные проверки жизненного цикла single и HA, восстановления после отказов, ресайза и смены пароля с настоящими Valkey и Envoy в выделенном k3s без HTTP API и PostgreSQL. Набор SHALL использовать три ноды для исходного стенда и сценариев без запасного хоста, добавляя четвёртую ноду для проверки восстановления полного HA после потери worker-ноды. Команда SHALL самостоятельно готовить свой стенд и тестовый образ оператора. Для потери оператора вместе с worker-нодой SHALL использоваться оператор внутри тестового k3s без одновременно работающей хостовой копии. K3s-проверки SHALL использовать отдельный тестовый профиль длительностей и показывать время сценариев; обычная сборка SHALL сохранять рабочие пороги. `run` SHALL запускать оператор на хосте с отдельным kubeconfig dev k3s. Команды `test-fast` и `test-full` MUST NOT оставаться публичными командами.

#### Scenario: Быстрые тесты оператора

- **WHEN** разработчик запускает `just test` в `operator`
- **THEN** этап проверок логики, CRD и reconcile выполняется через envtest без настоящих подов Valkey, после чего та же команда выполняет проверки жизненного цикла на отдельном k3s

#### Scenario: Запуск оператора с dev k3s

- **WHEN** разработчик запускает `just run` в `operator`
- **THEN** команда готовит CRD и RBAC и запускает manager через `go run` с kubeconfig dev-окружения под `tmp/k3s`

#### Scenario: Самостоятельные полные тесты

- **WHEN** единая команда доходит до тестов на k3s
- **THEN** тесты напрямую создают Kubernetes-объекты и проверяют TLS/SNI/AUTH, SET/GET, изоляцию, whitelist, рестарты и штатное удаление без API и PostgreSQL, затем выполняют обязательные проверки HA, аварий, ресайза и пароля

#### Scenario: Потеря worker-ноды

- **WHEN** единая команда проверяет восстановление после аварийной остановки agent
- **THEN** она выполняет сценарии без запасного хоста и с четвёртой нодой, включая потерю оператора вместе с primary, без ручного исправления ролей и finalizers ради успешного результата

#### Scenario: Стенд недоступен или тест не прошёл

- **WHEN** подготовка стенда либо проверка завершается неудачно
- **THEN** команда возвращает ненулевой код с причиной, не пропускает проверку молча и не снимает finalizers принудительно для получения успешного результата

#### Scenario: Анализ длительности

- **WHEN** этап реализации добавил или изменил сценарии оператора
- **THEN** разработчик видит их длительность, проверяет самые медленные ожидания и ускоряет обвязку без удаления настоящих воздействий и конечных проверок

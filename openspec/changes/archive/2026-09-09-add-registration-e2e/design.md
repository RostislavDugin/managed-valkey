## Context

В `tests/e2e` сейчас есть только план будущих сценариев. Корневой запуск считает
e2e ещё не реализованным, а CI выполняет только тесты API, оператора и клиентского
приложения. `scripts/test_environment.sh` уже умеет выделять для e2e отдельную
PostgreSQL и трёхнодовый k3s, а экран авторизации работает с настоящим API и после
регистрации открывает `/valkey/management`.

Удалить аккаунт через личный кабинет пока нельзя. Локальный и CI-стенды удаляют всю
свою временную базу после запуска; аккаунт ручной production-проверки остаётся.

## Goals / Non-Goals

**Goals:**

- создать минимальный исполняемый Playwright-набор, который проверяет регистрацию
  через браузер, API и PostgreSQL;
- использовать одну команду набора локально и в CI;
- заложить структуру для следующих сценариев из `tests/e2e/TODO.md`;
- сохранять полезные артефакты браузера при ошибке.

**Non-Goals:**

- запускать оператор или проверять Kubernetes в самом сценарии;
- создавать, изменять или удалять инстансы Valkey;
- реализовывать общий интеграционный набор;
- удалять аккаунт на рабочем сайте обходным путём.

## Decisions

### Отдельный пакет для e2e

Playwright и его конфигурация находятся в `tests/e2e`, а не в `web`. Набор проверяет
связку приложений и не принадлежит клиентскому приложению как изолированный тест.
Пакет использует TypeScript, закреплённую версию `@playwright/test` и только Chromium.
Повторы отключены, чтобы регистрация не создавала лишние аккаунты и не скрывала
нестабильность.

Альтернатива с добавлением Playwright в `web` смешала бы тесты одного приложения с
проверкой всего доступного пользовательского пути.

### Один сценарий для локального и рабочего окружений

Тест получает базовый URL из конфигурации, но не меняет последовательность действий.
Он открывает `/auth`, вводит новую почту, нажимает «Продолжить», дважды вводит
`testpassword` и создаёт аккаунт. Успех подтверждают адрес `/valkey/management` и
отображаемая в навигации почта. Последняя проверка также подтверждает, что сохранённый
JWT принят запросом `/me`.

Почта строится из идентификатора запуска, имени сценария и случайной части. Пароль не
попадает в название теста, журналы и вложения CI.

### Локальный стенд использует существующую изоляцию e2e

`just test-e2e` вызывает `scripts/test_environment.sh exec e2e`. Внутри выделенного
окружения отдельный сценарий применяет миграции, запускает API и Vite на свободных
loopback-портах, ждёт их готовности и затем запускает Playwright. Все дочерние
процессы завершаются по сигналу и при любом исходе теста.

Существующий профиль e2e продолжает готовить трёхнодовый k3s, хотя регистрация его не
использует. Это делает первый запуск тяжелее, но сохраняет один стенд для следующих
сценариев с оператором, Envoy и Valkey. Сам оператор до появления таких сценариев не
запускается.

Альтернатива с облегчённым профилем только для регистрации ускорила бы первый тест,
но создала бы второй способ подготовки e2e и потребовала бы менять подключённый набор
при добавлении жизненного цикла Valkey.

### Команды имеют разные режимы браузера, но один тест

`just test-e2e` запускает Chromium без окна на временном стенде.
`just test-e2e-headed` использует такой же стенд с видимым браузером.
`just test-prod` не готовит локальную базу и кластер, открывает видимый Chromium и
передаёт точный адрес `https://app.h3llo-demo.com`. Production-команда выбирает тест
с меткой `@prod`; первый сценарий регистрации имеет эту метку.

### Реализованный набор сразу становится обязательным

Корневой сценарий переносит `e2e` из списка будущих наборов в список выполняемых и
запускает его параллельно с API, оператором и `web`. `integration` остаётся будущим
набором.

CI получает отдельное задание `test-e2e`, которое зависит от всех заданий lint, но не
от других тестов. Оно устанавливает Go, Node.js, pnpm, `just`, зависимости пакета и
Chromium, затем вызывает `just test-e2e`. При ошибке CI сохраняет отчёт, снимок
экрана и диагностику тестового окружения без файлов с секретами. Трассировка
Playwright отключена для авторизации, поскольку она записывает введённый пароль и
тело запроса регистрации. Обвязка удаляет пароль из HTML-отчёта, проверяет обычные
файлы, ZIP и встроенные данные отчёта и разрешает публикацию только после успешной
проверки.

## Risks / Trade-offs

- Трёхнодовый k3s увеличивает время первого сценария. Используем уже принятый профиль
  e2e, чтобы не поддерживать временный облегчённый стенд.
- Регистрация ограничена по IP. Набор выполняет один запрос регистрации без повторов;
  параллельные сценарии появятся только после отдельного решения по ограничению
  частоты запросов в тестовом окружении.
- Поиск свободного порта имеет короткое окно гонки. Сценарий запуска проверяет
  завершение процессов и готовность HTTP, поэтому конфликт завершит набор явной
  ошибкой до Playwright.
- `just test-prod` оставляет аккаунт. Уникальная почта позволяет повторять проверку, а
  создание ресурсов Valkey в этом изменении запрещено.
- Отчёт Playwright записывает значение действия `fill()`. Пароль передаётся тесту
  через окружение и отсутствует в его исходном коде, а обвязка удаляет значение из
  отчёта. Если контрольная проверка всё же находит пароль, CI не публикует
  диагностические файлы.

## Migration Plan

Сначала добавляется пакет и локальная команда e2e, затем набор подключается к
корневому запуску и CI в том же изменении. После проверки план в `tests/e2e/TODO.md`
отмечает регистрацию и тестовую обвязку как реализованные, а сценарии Valkey остаются
неотмеченными.

Для отката удаляются e2e-зависимости и задание CI, а `e2e` возвращается в список
будущих наборов корневого запуска. Изменение не требует миграции пользовательских
данных или отката API.

## Context

См. [proposal.md](proposal.md). Срез `pages/valkey` уже содержит форму создания,
вкладку «Управление», модальные окна изменений и асинхронный клиент над
`localStorage`. После создания форма сразу переходит на адрес базы. Общий
`ValkeyLayout` остаётся смонтированным при этом переходе.

Полный пароль сейчас нигде не создаётся. `ValkeyInstance` хранит только
параметры базы со статусом `running`, а примеры подключения используют
`<PASSWORD>`. Настоящий API по `SYSTEM.md` будет принимать пароль от UI,
возвращать только маску и версии и применять смену асинхронно.

Незавершённое изменение `add-valkey-observability-ui` уже подняло схему
`mv_valkey_instances` до версии 4 и добавило журнал аудита. Эта работа опирается
на его текущую модель и не должна удалить миграции версий 1–3 или существующие
действия аудита.

## Goals / Non-Goals

**Goals:**

- ограничить жизнь полного пароля памятью текущего одноразового окна;
- провести создание и смену через формы будущего API без зависимости UI от
  `localStorage`;
- показать состояния загрузки, применения и ошибки внутри вкладки
  «Управление»;
- оставить весь сценарий в существующем срезе `pages/valkey`.

**Non-Goals:**

- имитировать Kubernetes Secret, ACL и работу оператора;
- хранить полный пароль для повторного просмотра;
- принимать пароль, придуманный пользователем;
- реализовывать HTTP-обработчики Go или менять контракт из `SYSTEM.md`.

## Decisions

### Полный пароль передаётся через память `ValkeyLayout`

Модель `valkey-credentials.ts` генерирует 24 случайных байта через
`crypto.getRandomValues` и кодирует их в base64url без padding. Одну функцию
используют создание и смена, поэтому формат не расходится между двумя
сценариями.

`ValkeyLayout` получает в контексте временный результат с идентификатором базы,
паролем и видом операции. Форма создания кладёт туда пароль только после
успешного ответа и затем переходит на страницу базы. Вложенная вкладка
«Управление» забирает результат для совпадающего идентификатора и открывает
одноразовое окно. Пароль не передаётся через `navigate(..., { state })`, потому
что состояние маршрута попадает в историю браузера.

При смене пароля тот же компонент окна проходит состояния подтверждения,
отправки и одноразового результата. Переход внутри одного окна не создаёт
короткого промежутка, когда секрет уже получен, но ещё не принадлежит видимому
элементу. Закрытие, размонтирование вкладки и обработчик `pagehide` очищают
значение. Идентификатор попытки не даёт позднему ответу снова открыть закрытое
окно.

Альтернатива с `sessionStorage` упростила бы переход после создания, но нарушила
бы запрет на постоянное хранение. Показ пароля на форме создания не выбран:
пользователь должен попасть на страницу готовой базы, где находятся адрес и
примеры подключения.

### Временный клиент хранит метаданные и имитирует применение

Схема `mv_valkey_instances` переходит на версию 5. Запись базы получает
`passwordHint`, `passwordVersion`, `appliedPasswordVersion` и служебное время
завершения демонстрационного применения. Миграция версий 1–4 сохраняет базы и
аудит; прежние демонстрационные базы получают маску `demo*****` и равные версии
1. После первой смены маска заменяется префиксом настоящего сгенерированного
значения.

`createInstance` принимает пароль, проверяет его формат, сохраняет только
первые четыре символа с `*****` и создаёт базу с версиями 1/1. Возвращаемый
`ValkeyInstance` полного пароля не содержит. Он остаётся у формы до передачи в
одноразовое окно.

Новый `api/valkey-credentials.ts` предоставляет аналоги получения учётных
данных и смены пароля. Смена проверяет владельца, формат пароля, ожидаемую
версию и отсутствие незавершённой операции. После принятия она увеличивает
`passwordVersion`, оставляет `appliedPasswordVersion` прежней, записывает маску
и событие аудита одной операцией. Полный пароль и тело запроса не сохраняются.

Заглушка отмечает версию применённой после короткой задержки. Чтение учётных
данных завершает просроченное демонстрационное применение, а вкладка опрашивает
метаданные, пока версии различаются. Так интерфейс показывает «Применяется» и
убирает статус после завершения без реализации оператора. Служебное
время не входит в публичный тип учётных данных.

Альтернатива с мгновенно равными версиями не позволяет проверить промежуточное
состояние. Вечное расхождение версий оставляло бы демонстрационную базу
заблокированной после первой смены.

### Учётные данные загружаются отдельным блоком вкладки

`ValkeyInstancePage` запрашивает учётные данные независимо от остальной базы.
Блок показывает пользователя `app`, маску, статус незавершённого применения и
действие смены рядом с адресом и текущим тарифом. Первая загрузка резервирует высоту строк, а ошибка
заменяет только блок учётных данных и содержит кнопку повтора.

Действие открывает короткое модальное окно. До отправки оно показывает точное
предупреждение о закрытии подключений. Для `degraded` добавляется сообщение о
возможной задержке. После принятия содержимое окна заменяется полным паролем,
кнопкой копирования и заметным предупреждением об одноразовом показе. Пароль не
попадает в уведомление об успехе.

Статус берётся из сравнения версий. Пока версии различаются, повторная смена
заблокирована. Ошибка ожидаемой версии закрывает результат, обновляет
метаданные и оставляет пользователю возможность начать новую попытку.

### Код остаётся в `pages/valkey`

Сценарий используют только форма создания и вкладка одной страницы базы. По
правилу pages-first модель, временный клиент, окна и состояние остаются внутри
`pages/valkey`; новые слои `features` и `entities` не создаются. Публичный
`index.ts` не экспортирует внутренние окна или модель.

### Событие расширяет текущую модель аудита

Тип `AuditAction`, подписи, проверка хранилища и тесты получают действие
`instance.password.rotate`. Временный клиент создаёт событие в той же записи,
где меняет версию и маску. Ошибка проверки не меняет ни учётные данные, ни
журнал.

## Risks / Trade-offs

- [Строку JavaScript нельзя гарантированно стереть из памяти процесса] → убрать
  все ссылки из React state и ref при каждом пути закрытия и не копировать
  значение в другие структуры.
- [Возврат страницы из bfcache может сохранить дерево React] → очищать
  временный результат на `pagehide`, включая событие с `persisted=true`.
- [Изменения пересекаются с активной работой над аудитом и версией хранилища]
  → строить версию 5 поверх текущей версии 4 и сохранить тесты миграции и все
  уже объявленные действия.
- [Буфер обмена живёт вне приложения после копирования] → копировать только по
  явному нажатию и прямо сообщить пользователю, что окно само буфер не очищает.
- [Демонстрационная задержка отличается от настоящего времени применения] →
  UI определяет готовность только по версиям и не зависит от длительности
  заглушки.

## Migration Plan

1. Расширить модель учётных данных и перевести хранилище с версии 4 на 5,
   сохранив чтение версий 1–4.
2. Добавить генерацию пароля и временные методы credentials, затем проверить,
   что постоянное состояние не содержит полного значения.
3. Передать первичный пароль через `ValkeyLayout` и добавить одноразовое окно на
   странице созданной базы.
4. Добавить блок учётных данных, смену пароля, опрос версий и событие аудита.
5. Проверить закрытие, переходы, перезагрузку, `pagehide`, поздний ответ,
   клавиатуру, обе цветовые схемы и поддерживаемые ширины.

Откат к сборке со схемой 4 потребует очистить демонстрационный ключ
`mv_valkey_instances`: старая сборка намеренно отвергает неизвестную версию.

## ADDED Requirements

### Requirement: E2E использует один общий полный стенд

Один запуск `just test-e2e` или `just test-e2e-headed` SHALL подготовить одну отдельную PostgreSQL, один трёхнодовый k3s из `k3s-server` и двух agents, две реплики Envoy, один процесс API со штатными фоновыми обработчиками, один процесс оператора и один процесс web. Все Playwright-сценарии запуска SHALL совместно использовать эти компоненты. Стенд MUST NOT создавать отдельную базу, кластер, API, оператор или web для каждого сценария.

#### Scenario: Общий стенд готов

- **WHEN** начинается выполнение локального каталога Playwright
- **THEN** API, оператор и web достигли готовности и используют базу и Kubernetes текущего e2e-запуска
- **AND** один browser worker последовательно выполняет сценарии на этом стенде

#### Scenario: Внешний порт перенаправлен на общий listener

- **WHEN** API публикует случайный порт хоста e2e, отличный от внутреннего порта listener Envoy
- **THEN** оператор создаёт SNI-listeners на своём `VALKEY_PUBLIC_PORT`
- **AND** Docker перенаправляет опубликованный API порт на закреплённый NodePort этого listener

#### Scenario: E2E работает рядом с другими наборами

- **WHEN** e2e и общий интеграционный либо другой тестовый набор готовятся одновременно
- **THEN** e2e использует собственные Compose project, базу, сеть, kubeconfig, сертификат, порты и диапазоны адресов

### Requirement: Публичный адрес e2e сохраняется при потере agent

API SHALL публиковать один адрес и порт Valkey на всё время e2e-запуска. Этот адрес SHALL оставаться прежним при остановке одного k3s-agent и удалении его объекта Node, пока `k3s-server` и хотя бы одна готовая реплика Envoy доступны. Восстановление agent MUST NOT требовать изменения адреса, уже показанного в личном кабинете.

#### Scenario: Worker с primary остановлен

- **WHEN** e2e останавливает принадлежащий своему стенду agent с primary, а server и другой Envoy остаются готовы
- **THEN** прежний публичный адрес продолжает принимать RO-трафик и после failover восстанавливает запись

#### Scenario: Agent возвращён

- **WHEN** остановленный agent возвращается или заменяется в том же e2e-стенде
- **THEN** он достигает Ready, маршрут к его Pod CIDR доступен с хоста, а публичный адрес личного кабинета не меняется

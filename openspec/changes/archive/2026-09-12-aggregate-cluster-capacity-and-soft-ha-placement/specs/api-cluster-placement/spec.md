## REMOVED Requirements

### Requirement: Конфигурация описывает ноды и резерв инфраструктуры

**Reason**: API переходит на два параметра полной суммарной ёмкости и фиксированный процентный запас, поэтому больше не моделирует одинаковые ноды.

**Migration**: Заменить понодовые параметры на `MANAGED_K8S_CLUSTER_VCPU` и `MANAGED_K8S_CLUSTER_RAM_GB` по контракту `api-cluster-capacity`.

### Requirement: Каждый принятый рост резервов имеет допустимое распределение

**Reason**: Предварительная раскладка противоречит новой модели суммарного учётного бюджета и запрещает совместное размещение HA на одной или двух нодах.

**Migration**: Проверять личную и кластерную квоты в API, а фактическое размещение передать Kubernetes. Неразмещаемый Pod отражается состоянием `Pending`.

### Requirement: Резерв согласован между запросами и подтверждениями

**Reason**: Согласованность резерва сохраняется как часть общей проверки квот, но больше не требует атомарного поиска раскладки.

**Migration**: Использовать правила резерва и общей блокировки из `api-valkey-quotas` без чтения списка резервов для placement-поиска.

### Requirement: Отказ размещения отличается от общей нехватки

**Reason**: API больше не доказывает возможность раскладки и поэтому не формирует отдельный отказ размещения или таймаут поиска.

**Migration**: Клиенты должны обрабатывать `cluster_quota` для превышения суммарного бюджета и наблюдаемый статус инстанса для ограничений Kubernetes. Ответы `placement_capacity` и `placement_check_timeout` удаляются.

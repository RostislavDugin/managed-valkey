## Why

Таблица и HTTP API метрик уже работают, но остаются пустыми: фоновая синхронизация API не переносит снимки из `status.metrics` ресурса `ValkeyInstance`. Нужен импорт с проверкой идентичности процессов и ограничением срока хранения, который можно проверить без запуска оператора.

## What Changes

- Расширить общий контракт `ValkeyInstanceStatus` снимками `metrics`, не добавляя сбор метрик или другую логику оператора.
- Переносить допустимые снимки из CR в `valkey_node_metrics` внутри фоновой синхронизации API.
- Проверять принадлежность снимка текущему процессу по `ordinal`, Pod UID, container ID и `runId`; повреждённые, неизвестные и просроченные снимки не сохранять.
- Защитить повторный импорт через `ON CONFLICT DO NOTHING` и не связывать вставку метрик с изменением основного наблюдения инстанса.
- Загружать `VALKEY_METRICS_RETENTION` с значением по умолчанию `168h`, не импортировать более старые снимки и ежедневно удалять просроченные строки.
- Проверить путь от записи `status.metrics` административным клиентом теста до существующего HTTP API метрик на настоящих PostgreSQL и k3s, без запуска оператора.
- Проверить существующий экран мониторинга на данных нового источника; менять frontend только при несовместимости с действующим HTTP-контрактом.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `api-valkey-sync`: фоновый импорт читает `status.metrics`, проверяет идентичность снимков и сохраняет их независимо от изменений остальных наблюдений.
- `api-valkey-metrics`: история ограничивается на записи и физически очищается по настроенному сроку хранения.

## Impact

Изменение затрагивает общий тип и схему CRD `ValkeyInstance`, пакеты синхронизации, хранилища и конфигурации в `api`, запуск фоновых задач API и интеграционные тесты. Сборщик метрик, `INFO`, `metrics.k8s.io` и тесты жизненного цикла оператора остаются вне изменения. Публичный маршрут и DTO `GET /v1/managed/valkey/instances/{id}/metrics` не меняются; новые зависимости Go не требуются.

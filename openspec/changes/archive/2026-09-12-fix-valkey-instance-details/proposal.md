## Why

Карточка Valkey не даёт единый контракт подключения для `single` и `ha`, а окно обслуживания нельзя задать при создании или открыть из соответствующей строки карточки. Несогласованные подписи и устаревший `operator/TODO.md` дополнительно расходятся с уже реализованным поведением и тестовым покрытием.

## What Changes

- Всегда создавать и возвращать два стабильных адреса: primary `<slug>.<domain>` и адрес чтения `<slug>-ro.<domain>`. В `single` оба адреса ведут на единственный процесс; адрес чтения не означает наличие физической реплики и не запрещает запись на уровне Valkey.
- Показывать оба адреса на карточке каждого инстанса и в примерах подключения с явным разделением primary и чтения; отображаемые и копируемые значения SHALL иметь вид `redis://<host>:<port>`.
- Принимать окно обслуживания в запросе создания, сохранять его вместе с инстансом и добавить отдельное действие изменения или очистки окна на карточке.
- Использовать единое пользовательское название «Белый список» в форме создания, карточке, окне изменения, уведомлениях и аудите, не меняя поля HTTP API и внутренние идентификаторы `whitelist`.
- Исправить подпись времени создания с «Создана» на «Создано», сохранив грамматически верную фразу «Создана база» в журнале аудита.
- Удалить выполненные пункты `operator/TODO.md`, сам файл, если он останется пустым, и действующие ссылки, которые называют реализованные unit-, интеграционные и e2e-сценарии будущей работой. Исторические архивы OpenSpec не менять.
- Обновить проверки API, оператора, web, общей интеграции и Playwright e2e под новый контракт адресов и настройки окна обслуживания.
- Во время реализации запускать только затронутые тесты и точечные сценарии; не запускать агрегатные `test-full` и остальные неизменённые наборы.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `api-valkey-management`: API всегда возвращает адрес чтения и принимает окно обслуживания при создании.
- `web-valkey-management`: форма и карточка показывают новые поля и согласованные пользовательские подписи.
- `single-instance-lifecycle`: `single` получает отдельный публичный адрес чтения, ведущий на единственный процесс.
- `test-orchestration`: обязательные наборы проверяют оба адреса и пользовательский путь настройки окна обслуживания.
- `backend-foundation`: действующая документация больше не требует завершённых списков будущих тестов.

## Impact

Изменение затрагивает контракт создания и DTO Valkey, сохранение адресов и окна обслуживания, ресурсы Gateway API для `single`, страницу создания и карточку инстанса. Потребуются миграция существующих строк с пустым `host_ro`, обновление синхронизации API с CR, unit- и компонентные тесты, точечные сценарии общей интеграции и Playwright e2e. Активные системные документы и инструкции оператора нужно согласовать с фактическим покрытием; архивные изменения OpenSpec остаются неизменными.

## REMOVED Requirements

### Requirement: Локальные команды оператора

**Reason**: Требование каркаса включает отсутствие интеграционных тестов. Его заменяет требование «Команды запуска и проверки оператора» с действующим test-full.

**Migration**: Сохранить имена публичных команд и правила test-fast/run; заменить заглушку test-full самостоятельными интеграционными тестами.

### Requirement: Проверки состояния оператора

**Reason**: Требование каркаса включает пустой reconcile. Его заменяет требование «Готовность manager и управление инстансами» с предметным контроллером.

**Migration**: Сохранить проверки процесса и manager, заменить проверку пустого reconcile сценариями управления single.

## ADDED Requirements

### Requirement: Команды запуска и проверки оператора

Каталог `operator` SHALL содержать `Justfile` с публичными командами `test-fast`, `test-full` и `run`. Быстрая проверка MUST NOT требовать работающего dev-кластера. `run` SHALL запускать оператор как процесс хоста с отдельным kubeconfig dev k3s. `test-full` SHALL выполнять интеграционные проверки жизненного цикла single с настоящими Valkey и Envoy на k3s без HTTP API и PostgreSQL.

#### Scenario: Быстрые тесты оператора

- **WHEN** разработчик запускает `just test-fast` в `operator`
- **THEN** выполняются тесты логики, CRD и reconcile через envtest без ожидания запуска настоящих подов Valkey

#### Scenario: Запуск оператора с dev k3s

- **WHEN** разработчик запускает `just run` в `operator`
- **THEN** команда генерирует CRD и RBAC и запускает manager через `go run` с kubeconfig из `tmp/k3s`

#### Scenario: Самостоятельные полные тесты

- **WHEN** разработчик запускает `just test-full` с подготовленным k3s и единственной тестовой копией оператора
- **THEN** тесты напрямую создают входные Kubernetes-объекты, проверяют TLS/SNI/AUTH, SET/GET, изоляцию, whitelist, рестарты и штатное удаление без API и PostgreSQL

#### Scenario: Стенд недоступен или тест не прошёл

- **WHEN** необходимые компоненты стенда отсутствуют либо проверка завершилась неудачно
- **THEN** команда завершается с ненулевым кодом и понятной причиной, не пропускает проверку молча и не снимает finalizers принудительно

### Requirement: Готовность manager и управление инстансами

Оператор SHALL предоставлять проверки живого процесса и готовности manager. Контроллер SHALL управлять жизненным циклом single согласно capability single-instance-lifecycle. Готовность manager MUST NOT означать публичную готовность инстансов.

#### Scenario: Manager запущен

- **WHEN** оператор подключился к Kubernetes и запустил manager
- **THEN** проверки живого процесса и готовности отвечают успешно

#### Scenario: Ресурс попал в reconcile

- **WHEN** контроллер получает полный поддерживаемый ValkeyInstance
- **THEN** он приводит ресурсы к принятой конфигурации и записывает подтверждённые наблюдения в status

#### Scenario: Инстанс ещё не готов

- **WHEN** manager работает, но инстанс ожидает готовности маршрута или процесса
- **THEN** manager остаётся готовым, а status инстанса не сообщает running до выполнения его проверок

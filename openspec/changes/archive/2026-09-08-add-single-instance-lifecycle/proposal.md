## Why

Оператор пока только запускает manager: из `ValkeyInstance` нельзя получить работающий Valkey. Первое создание и удаление `single` позволит проверить оператор отдельно от HTTP API и разработки авторизации, подавая входные объекты через Kubernetes.

## What Changes

- Реализовать первоначальное создание `single`: служебные учётные данные, конфигурация Valkey, StatefulSet, Services и NetworkPolicy.
- Подготовить публичный маршрут через Envoy с TLS и первоначальным whitelist; включать `app` и подтверждать `running` только после проверок из SYSTEM-DETAIL.md.
- Сохранять идентичности процессов и стадии операций в CR; продолжать создание и удаление после рестарта оператора и потери ответа на команду.
- Реализовать наблюдение здоровья и безопасную замену подтверждённо остановленного процесса single. Недоказанная остановка блокирует допуск замены к клиентам.
- Удалять инстанс через finalizer, закрывая доступ и подтверждая остановку процессов до удаления Secret. Namespace остаётся ответственностью вызывающей стороны.
- Добавить самостоятельные тесты оператора на k3s без API и PostgreSQL и заменить заглушку `test-full`.
- Диагностировать неподдерживаемый режим и изменения настроек, сохраняя рабочую конфигурацию без ложного подтверждения поколения.

HA, ресайз, ротация пароля, изменение whitelist после принятия первоначальной конфигурации, сбор метрик и автоматическое восстановление BUSY/SIGSTOP относятся к следующим изменениям. Это ограниченный этап реализации v1, а не заявление о выполнении всего SYSTEM.md.

## Capabilities

### New Capabilities

- `single-instance-lifecycle`: контракт первоначальной конфигурации, запуск single, публичная готовность, наблюдение, продолжение операций и безопасное удаление.

### Modified Capabilities

- `backend-foundation`: предметный reconcile вместо пустого контроллера и реальные самостоятельные интеграционные тесты оператора.

## Impact

Изменение затронет публичные типы `operator/api/v1alpha1`, генерируемые CRD/RBAC, `operator/internal/operator`, новый `operator/internal/valkey`, конфигурацию и тесты оператора, `operator/Justfile`. Потребуются valkey-go и типы Gateway API/Envoy Gateway в общем Go-модуле с закреплёнными версиями. При необходимости уточняются dev-манифесты и bootstrap для доступа оператора и тестовых клиентов. HTTP API, PostgreSQL и frontend в реализацию не входят. Контракт Secret должен быть пригоден для последующей доставки из API.

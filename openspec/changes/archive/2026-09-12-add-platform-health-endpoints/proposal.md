## Why

Внешняя HTTP-проверка сейчас видит только готовность API к работе с PostgreSQL. Она не замечает потерю связи с Kubernetes, застрявшее создание или изменение инстанса и недоступность публичных адресов Valkey.

## What Changes

- Добавляется публичный `GET /health`, который одним ответом сообщает о PostgreSQL, Kubernetes, застрявших операциях и сохранённых состояниях активных инстансов.
- Добавляется публичный `GET /valkey-health`, который получает URI primary и read-only через заголовки, параллельно проверяет TLS, AUTH и PING и возвращает результат по каждому адресу.
- Проверка Valkey принимает только адреса управляемого домена и рабочего порта, не пишет переданные URI и пароли в ответы или логи и не выполняет команды чтения или записи данных.
- Краткие сбои не сглаживаются внутри API. Uptime Kuma повторяет запросы и поднимает тревогу только после шести неудачных повторов с интервалом 30 секунд.
- В рабочей конфигурации Caddy открываются оба маршрута и ограничивается частота запросов к ним.
- В объём не входят отдельный тестовый инстанс Valkey, Metrics Server, глубокая проверка внутренних объектов Kubernetes, новый контроллер состояния и изменение RBAC оператора.

## Capabilities

### New Capabilities

- `platform-health`: Сводная проверка состояния платформы и проверка публичных TLS-подключений к primary и read-only адресам Valkey.

### Modified Capabilities

- `backend-environments`: Caddy передаёт новые служебные маршруты в API и ограничивает частоту публичных проверок.

## Impact

Изменение затрагивает HTTP-маршрутизатор и обработчики API, чтение состояния инстансов из PostgreSQL, существующий клиент Kubernetes, подключение к Valkey через TLS, конфигурацию Caddy и проверки API и рабочего окружения. Миграции базы, изменения CRD и новые права Kubernetes не нужны.

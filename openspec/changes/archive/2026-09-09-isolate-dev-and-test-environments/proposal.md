## Why

Тесты оператора сейчас используют dev-кластер и обрабатывают все его ValkeyInstance. Добавление тестов синхронизации API требует независимых окружений, чтобы параллельные проверки не меняли объекты друг друга и данные разработчика.

## What Changes

- Постоянный dev-кластер на трёх нодах и четыре независимых тестовых кластера: API на одной ноде, оператор, интеграционные API + operator и Playwright e2e на трёх нодах каждый.
- Общая параметризованная подготовка окружений с отдельными сетями, портами, kubeconfig, томами и базами PostgreSQL.
- Корневой `just run` готовит dev-инфраструктуру, устанавливает CRD, RBAC и инфраструктуру шлюза, применяет миграции и запускает оператор, API и фронт. Dev-данные сохраняются между запусками.
- **BREAKING**: `operator/just test-fast` и `operator/just test-full` заменяются единым `just test`; `api/just test` также выполняет весь набор подсистемы.
- Корневой `just test` параллельно запускает все существующие наборы, включая медленные, с отдельными журналами и итоговым кодом ошибки. GitHub Actions использует те же команды в независимых jobs.
- Тестовые команды проверяют генерацию без перезаписи исходников; очистка ограничивается ресурсами конкретного запуска.
- Краткое описание окружений и команд в `SYSTEM.md`, детали подготовки и очистки в `SYSTEM-DETAIL.md`, актуализация инструкций приложений.

## Capabilities

### New Capabilities

- `test-orchestration`: единый запуск наборов, владение тестовыми окружениями, сбор результатов и диагностики; границы будущих сквозных проверок.

### Modified Capabilities

- `backend-environments`: независимые dev/test-окружения, общий bootstrap и полный локальный запуск.
- `backend-foundation`: единые команды тестов API и оператора, генерация без изменений рабочего дерева.
- `ci-cd`: полный набор тестов подсистем в независимых jobs и подключение сквозных наборов по мере их появления.

## Impact

Затрагиваются корневой и локальные Justfile, dev/test Compose, scripts подготовки k3s и kubeconfig, тестовая обвязка оператора и API, CI и документация. Production-развёртывание и контракт ValkeyInstance не меняются.

Реализация синхронизации PostgreSQL ↔ CR остаётся отдельным изменением. Этот change готовит окружения и точки запуска будущих API + operator и Playwright-наборов, но не реализует синхронизацию, ресайз, ротацию пароля или отсутствующие сквозные сценарии. Отсутствующий набор отмечается явно; успешный запуск существующих тестов не объявляется проверкой ещё не реализованной цепочки.

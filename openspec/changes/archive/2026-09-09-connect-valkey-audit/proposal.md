## Why

События Valkey уже сохраняются в `audit_logs`, но API не умеет читать журнал, а вкладка «Аудит» показывает статичное пустое состояние. Пользователь не видит историю действий, хотя данные уже есть в PostgreSQL.

## What Changes

- Добавить постраничное чтение событий выбранного инстанса через `GET /v1/managed/valkey/instances/{id}/audit` после общей проверки владельца.
- Оставить аудит отдельным прикладным сервисом: `valkey` зависит только от узкого контракта записи, а HTTP-слой отдельно обращается к сервисам `valkey` и `audit`.
- Кодировать позицию страницы в непрозрачном base64url-курсоре и проверять `limit` и `before` до обращения к хранилищу.
- Подключить вкладку «Аудит» к HTTP API и вернуть журнал, сгруппированный по местным календарным дням, с состояниями загрузки, пустого ответа и ошибки.
- Показывать все действия Valkey, включая изменение белого списка, и загружать старые события по кнопке «Показать ещё».
- Проверить HTTP-контракт на настоящей PostgreSQL и покрыть клиент, группировку и состояния страницы тестами.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `api-audit`: добавить чтение журнала выбранного инстанса, проверку параметров и курсорную пагинацию при сохранении границы отдельного сервиса аудита.
- `web-valkey-observability`: заменить состояние недоступности журнала данными серверного API и определить поведение всех состояний страницы.

## Impact

Изменения затронут пакеты `api/internal/audit`, `api/internal/store` и `api/internal/api`, сборку зависимостей API, а также срез `web/src/pages/valkey`. Схема PostgreSQL и внешние зависимости не меняются.

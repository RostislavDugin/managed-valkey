## MODIFIED Requirements

### Requirement: Журнал аудита сгруппирован по дням

Экран аудита SHALL показывать время, понятное название действия и почту автора. События SHALL идти от новых к старым и группироваться по календарной дате в местном часовом поясе браузера.

#### Scenario: События сегодня и вчера

- **WHEN** журнал содержит события за текущий и предыдущий местный день
- **THEN** группы называются «Сегодня» и «Вчера»

#### Scenario: Более старое событие

- **WHEN** событие относится к более ранней дате
- **THEN** заголовок группы содержит день, название месяца и год, когда он отличается от текущего

#### Scenario: Время события

- **WHEN** пользователь читает строку журнала
- **THEN** рядом показаны точное местное время и относительная подпись вида «5 минут назад»
- **AND** относительная подпись пересчитывается, пока страница открыта

#### Scenario: Известное действие

- **WHEN** журнал содержит действие из фиксированного списка аудита Valkey
- **THEN** экран показывает его русское название и подходящую иконку
- **AND** техническое имя действия остаётся доступно в строке

#### Scenario: Изменение белого списка

- **WHEN** журнал содержит `instance.whitelist.update`
- **THEN** экран показывает название «Изменён доступ по IP», техническое имя действия и подходящую иконку

### Requirement: Журнал загружается страницами

Первый запрос журнала SHALL возвращать до 50 новых событий. При наличии более старых событий экран SHALL показывать кнопку «Показать ещё» и передавать полученный курсор следующему запросу без разбора.

#### Scenario: Есть следующая страница

- **WHEN** ответ содержит курсор продолжения
- **THEN** пользователь видит кнопку «Показать ещё»
- **AND** нажатие добавляет старые события после уже показанных
- **AND** события остаются в правильных группах дат без повторов

#### Scenario: Журнал загружен полностью

- **WHEN** ответ не содержит курсор продолжения
- **THEN** кнопка «Показать ещё» не показывается

#### Scenario: Повторное нажатие во время загрузки

- **WHEN** запрос следующей страницы ещё выполняется
- **THEN** кнопка «Показать ещё» показывает загрузку и не запускает второй запрос

### Requirement: Экраны обрабатывают состояния данных

До подключения HTTP API метрик мониторинг SHALL показывать состояние недоступности. После подключения своего источника мониторинг SHALL обрабатывать загрузку, данные, пустой ответ и ошибку по правилам этого требования. Подключённый экран аудита SHALL иметь отдельные состояния загрузки, данных, пустого ответа и ошибки. Ошибка одного экрана MUST NOT скрывать каркас страницы базы.

#### Scenario: Первая загрузка

- **WHEN** экран ожидает первый ответ серверного API
- **THEN** он показывает скелетон с зарезервированным местом под содержимое

#### Scenario: Пустые метрики

- **WHEN** подключённый клиент метрик возвращает окно без измерений
- **THEN** мониторинг сообщает, что измерений пока нет
- **AND** выбранное окно остаётся доступно

#### Scenario: Пустой журнал

- **WHEN** клиент возвращает пустой список событий
- **THEN** аудит сообщает, что действий с базой пока не было

#### Scenario: Ошибка загрузки

- **WHEN** клиент не может вернуть метрики или аудит
- **THEN** соответствующий экран показывает причину и кнопку повторной загрузки

#### Scenario: Пользователь покинул журнал

- **WHEN** запрос аудита завершается после перехода к другой базе или ухода со страницы
- **THEN** его результат не появляется на новом экране

### Requirement: Наблюдаемость ожидает серверные источники

Вкладка мониторинга SHALL сохранять каркас и навигацию и показывать «Метрики пока недоступны» до подключения HTTP API метрик. Она MUST NOT генерировать измерения или опрашивать несуществующий endpoint. Вкладка аудита SHALL читать только серверный журнал выбранной базы через `GET /v1/managed/valkey/instances/{id}/audit`. Она MUST NOT читать локальные события или выдавать ошибку API за пустую историю. Управление SHALL оставаться доступным при ошибке любого источника наблюдаемости.

#### Scenario: У базы уже есть серверный аудит

- **WHEN** пользователь открывает аудит базы
- **THEN** экран запрашивает серверный журнал этой базы
- **AND** показывает данные, пустое состояние или ошибку в соответствии с ответом

#### Scenario: Открытие мониторинга

- **WHEN** пользователь открывает мониторинг до реализации API метрик
- **THEN** экран не показывает демонстрационные значения или нули вместо отсутствующих измерений

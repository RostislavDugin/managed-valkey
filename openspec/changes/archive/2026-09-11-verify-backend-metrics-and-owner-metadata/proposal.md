## Why

Общий интеграционный набор проверяет создание Valkey через настоящий API и оператор, но пока не подтверждает две недавно добавленные части сквозного пути: импорт собранных оператором метрик в PostgreSQL с последующей выдачей через HTTP и перенос метаданных владельца в Kubernetes. Из-за этого поломка связи между уже покрытыми компонентами может пройти обязательную проверку CI.

## What Changes

- Расширить существующий сценарий создания проверкой доступности метрик через публичный HTTP API.
- Проверить метки идентичности и роли, а также аннотацию с адресом электронной почты владельца на доступных тесту объектах Kubernetes.
- Сохранить текущие границы набора: пользовательские действия проходят только через HTTP, клиент Kubernetes остаётся только читающим, прямого доступа к PostgreSQL нет.
- Не добавлять новый параллельный сценарий и отдельный экземпляр Valkey.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `test-orchestration`: общий интеграционный набор дополнительно подтверждает сквозную доставку метрик и метаданных владельца.

## Impact

Изменятся только тестовый клиент HTTP и сценарии в `tests/integrations`, а также их локальные модульные проверки. Публичный API, рабочий код API и оператора, схема PostgreSQL и CRD не меняются.

## MODIFIED Requirements

### Requirement: Сессия хранится в браузере

Признаком сессии SHALL быть JWT в `localStorage` под ключом `mv_token`. Токен SHALL содержать стабильный `user_id` в поле `sub` и разбираемый на клиенте срок действия в поле `exp`. При восстановлении сессии консоль SHALL проверить токен запросом `GET /v1/me` и получить из ответа актуальные UUID и почту пользователя. Серверной таблицы сессий нет, выход это удаление токена.

#### Scenario: Сессия переживает перезагрузку

- **WHEN** пользователь с действующим токеном перезагружает страницу
- **THEN** консоль проверяет токен через `/v1/me`
- **AND** пользователь остаётся в консоли и на той же странице
- **AND** объект сессии содержит `userId`, `email`, `expiresAt` и токен

#### Scenario: Пользователь заблокирован после входа

- **WHEN** `/v1/me` отвечает `UNAUTHORIZED` для JWT заблокированного пользователя
- **THEN** консоль удаляет `mv_token` и открывает `/auth` с уведомлением

#### Scenario: Ресурс связывается с пользователем

- **WHEN** консоль отправляет запрос на создание ресурса с действующим серверным JWT
- **THEN** API связывает ресурс с `userId` из проверенного поля `sub`
- **AND** почта и переданные клиентом идентификаторы не используются как идентификатор владельца

#### Scenario: Выход по кнопке

- **WHEN** пользователь нажимает «Выйти»
- **THEN** обработчик удаляет `mv_token`
- **AND** открывается `/auth` на первом шаге
- **AND** другие вкладки того же браузера завершают эту сессию после события `storage`

## REMOVED Requirements

### Requirement: Временная реализация без сервера

**Reason**: Сервер предоставляет постоянные аккаунты и маршруты `/v1/auth/*`, поэтому хранение открытых паролей и демонстрационных JWT в браузере больше не требуется.

**Migration**: Удалить `mv_users` и пометку демонстрационного режима. Существующие локальные аккаунты не переносятся; пользователь регистрирует аккаунт в API. `mv_token` сохраняет имя ключа, но принимает только JWT сервера.

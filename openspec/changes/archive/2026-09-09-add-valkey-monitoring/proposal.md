## Why

Вкладка мониторинга уже есть во фронтенде, но показывает заглушку, потому что API не хранит и не читает историю метрик. Нужен рабочий путь от PostgreSQL до графиков, который можно проверить до реализации фонового сбора данных из Kubernetes.

## What Changes

- Добавить таблицу `valkey_node_metrics` для снимков метрик отдельных нод Valkey.
- Добавить `GET /v1/managed/valkey/instances/{id}/metrics` с проверкой владельца, фиксированными окнами и агрегацией временных рядов.
- Подключить вкладку мониторинга к HTTP API и вернуть сводку, четыре графика, выбор окна и нод, последовательное обновление и состояния загрузки, ошибки и пустого ответа.
- Показывать текст «Метрик пока нет», когда за выбранное окно нет данных.
- Не добавлять фоновый сбор и импорт метрик из Kubernetes или оператора, очистку истории, таблицу состояния нод и HTTP API аудита.

## Capabilities

### New Capabilities

- `api-valkey-metrics`: хранение снимков метрик и чтение агрегированных временных рядов через защищённый HTTP API.

### Modified Capabilities

- `web-valkey-observability`: вкладка мониторинга получает серверные метрики вместо заглушки и обрабатывает все состояния запроса.

## Impact

Изменение затрагивает миграции PostgreSQL, хранилище и сервис Valkey в `api`, маршрут `/v1/managed/valkey/instances/{id}/metrics`, клиент и компоненты `pages/valkey` во фронтенде, а также интеграционные и компонентные тесты. Новые внешние зависимости не нужны.

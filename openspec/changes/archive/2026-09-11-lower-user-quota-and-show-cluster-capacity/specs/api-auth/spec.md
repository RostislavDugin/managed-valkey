## ADDED Requirements

### Requirement: Существующие аккаунты получают новую стандартную квоту

Миграция SHALL установить всем существующим аккаунтам квоту 4 vCPU / 12 GB. Она MUST NOT менять, уменьшать или удалять существующие инстансы. Аккаунт, расход которого после миграции превышает новый лимит RAM, SHALL сохранять доступ к своим данным и сможет уменьшать расход по действующим правилам квоты.

#### Scenario: Существующие квоты понижены

- **WHEN** миграция применяется к базе с аккаунтами, имеющими прежнюю стандартную квоту 4 vCPU / 16 GB
- **THEN** каждая существующая строка `user_quotas` содержит лимиты 4 vCPU / 12 GB
- **AND** строки инстансов и их выбранные размеры не меняются

#### Scenario: Расход оказался выше нового лимита

- **WHEN** существующий аккаунт использует больше 12 GB RAM в момент миграции
- **THEN** его инстансы продолжают существовать без принудительного изменения размера
- **AND** последующие изменения подчиняются правилу квоты, уменьшенной ниже занятого объёма

## MODIFIED Requirements

### Requirement: Регистрация создаёт аккаунт и начальную квоту

API SHALL предоставлять `POST /v1/auth/register` с телом `{email, password}` и обязательным заголовком `Idempotency-Key` в формате UUID. Пароль SHALL содержать от 8 символов до 72 байт UTF-8. В одной транзакции API SHALL создать пользователя с UUIDv7 и `is_blocked=false`, квоту 4 vCPU и 12 GB, запись аудита `user.register` через общий внутренний сервис аудита и запись ключа регистрации. Пароль MUST храниться только как bcrypt-хеш с cost 12.

#### Scenario: Успешная регистрация

- **WHEN** клиент отправляет свободную допустимую почту, допустимый пароль и новый ключ
- **THEN** API создаёт один аккаунт и его квоту
- **AND** отвечает `200` с JWT в поле `token`

#### Scenario: Почта уже занята

- **WHEN** клиент регистрирует существующую почту с новым ключом
- **THEN** API отвечает `409 CONFLICT`
- **AND** не создаёт пользователя, квоту или запись успешной регистрации

#### Scenario: Пароль слишком короткий

- **WHEN** пароль содержит меньше 8 символов
- **THEN** API отвечает `400 VALIDATION_FAILED`

#### Scenario: Пароль не помещается в bcrypt

- **WHEN** пароль длиннее 72 байт UTF-8
- **THEN** API отвечает `400 VALIDATION_FAILED`

#### Scenario: Ключ регистрации отсутствует или повреждён

- **WHEN** клиент не передаёт `Idempotency-Key` или передаёт значение не в формате UUID
- **THEN** API отвечает `400 VALIDATION_FAILED`

#### Scenario: Конкурентная регистрация одной почты

- **WHEN** два запроса с разными ключами одновременно регистрируют одну нормализованную почту
- **THEN** ровно один запрос создаёт аккаунт
- **AND** второй получает `409 CONFLICT`

#### Scenario: Отказ аудита регистрации

- **WHEN** сервис аудита не может сохранить событие
- **THEN** пользователь, квота и ключ откатываются, API возвращает ошибку без JWT

### Requirement: Текущий пользователь доступен через API

API SHALL предоставлять защищённый `GET /v1/me` и возвращать пользователя, его квоту и текущее использование ресурсов. Лимиты SHALL читаться из user_quotas. Использование SHALL суммировать резерв Valkey пользователя с deleted_at IS NULL независимо от фазы: число процессов умножается на покомпонентный максимум desired/applied размера. Без ресурсов использование SHALL быть нулевым. Квота и usage SHALL читаться из согласованного снимка; формат quota {max_vcpu,max_ram_gb} и usage {used_vcpu,used_ram_gb} SHALL сохраняться.

#### Scenario: Пользователь восстанавливает сессию

- **WHEN** клиент вызывает `/v1/me` с действующим JWT
- **THEN** ответ содержит UUID и нормализованную почту пользователя, актуальную квоту (по умолчанию 4 vCPU и 12 GB) и текущее использование

#### Scenario: Запрос без JWT

- **WHEN** клиент вызывает `/v1/me` без заголовка авторизации
- **THEN** API отвечает `401 UNAUTHORIZED`

#### Scenario: Удаление ещё не подтверждено

- **WHEN** у базы есть deletion_requested_at, но нет deleted_at
- **THEN** /v1/me продолжает учитывать её резерв

#### Scenario: Квоту изменили вручную

- **WHEN** лимиты пользователя изменены в PostgreSQL
- **THEN** следующий /v1/me возвращает новые лимиты и фактический резерв

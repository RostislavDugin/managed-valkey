## Context

См. [proposal.md](proposal.md). Сейчас `web` отсутствует. Требования к нему находятся в `SYSTEM.md`: SPA на React, маршрутизация в браузере, прокси `/v1` в режиме разработки, пакеты из `pnpm`, Mantine, Tailwind без Preflight и графики Mantine Charts.

Каталог `design` содержит 20 файлов: документацию, CSS-токены, тему Mantine, JSON-копию токенов и автономную HTML-витрину. Часть токенов является снимком существующего продукта, а аудит контраста уже описывает обязательные исправления. Файл `tailwind-brand.css` и документ о лендинге относятся к другому интерфейсу; значения брендовых цветов в них помечены как гипотеза.

Проектные навыки сейчас хранятся отдельно в `.agents/skills` и `.claude/skills`. Копии OpenSpec отличаются только названиями команд, которые агенты предлагают пользователю. `humanizer` уже подключён в `.claude/skills` символической ссылкой.

## Goals / Non-Goals

**Goals:**

- Получить минимальное приложение, на котором можно начинать реализацию экранов из `SYSTEM.md`.
- Оставить одно место для изменения каждого дизайн-токена и каждого проектного навыка.
- Сделать ограничения FSD, форматирования и статического анализа исполняемыми проверками.
- Не потерять применимые правила из `design` при удалении каталога.

**Non-Goals:**

- Не реализовывать вход, регистрацию, список инстансов и другие продуктовые экраны.
- Не создавать общий клиент API до появления первого запроса.
- Не переносить дизайн лендинга `h3llo.cloud` в консоль Managed Valkey.
- Не добавлять Storybook, Vitest и сквозные тесты в начальный каркас.
- Не менять API, backend, окружение контейнеров и изменённый пользователем `SYSTEM.md`.

## Decisions

### 1. Версии и зависимости

Использовать текущие совместимые версии, проверенные при подготовке изменения:

- Node.js 24.18.0 и `pnpm@10.33.0`;
- React и React DOM 19.2.8;
- TypeScript 7.0.2, Vite 8.2.2 и `@vitejs/plugin-react` 6.1.1;
- React Router 8.3.1;
- Mantine 9.6.0 для `@mantine/core`, `@mantine/hooks`, `@mantine/form`, `@mantine/charts` и `@mantine/notifications`, плюс совместимый Recharts;
- Tailwind CSS и `@tailwindcss/vite` 4.3.3;
- Oxlint 1.82.0, Oxfmt 0.67.0 и `oxc-config-mantine` 1.0.3;
- Steiger и `@feature-sliced/steiger-plugin` для проверки FSD;
- `lucide-react` для иконок, а также пакеты variable-font Manrope и Roboto Mono.

Связанные пакеты Mantine фиксируются на одной точной версии. Остальные версии фиксирует `pnpm-lock.yaml`; `package.json` также получает поле `packageManager`.

Начальный каркас создаётся официальным генератором Vite:

```bash
pnpm create vite web --template react-ts --no-interactive
```

Сразу после генерации удаляются стандартная настройка ESLint, зависимости ESLint, демонстрационные изображения и стили. Затем устанавливаются зависимости из списка выше и создаётся структура FSD. Такой порядок оставляет стандартные `index.html`, точку входа, настройки TypeScript и Vite, но не переносит в проект лишние решения шаблона.

Альтернатива: использовать готовый шаблон Mantine для Vite. Он также содержит Oxfmt и Oxlint, но приносит Yarn, Storybook, Vitest и Stylelint, которые не входят в объём изменения. Очистка такого шаблона сложнее, чем настройка Mantine поверх `react-ts`.

### 2. Начальная структура FSD

Использовать FSD v2.1 с подходом pages-first:

```text
web/src/
  main.tsx
  app/
    App.tsx
    index.ts
    providers/
    routes/
    styles/
  pages/
    home/
      index.ts
      ui/
  shared/
    config/
```

Создавать только каталоги с используемыми файлами. `features`, `entities` и `widgets` появятся после возникновения стабильной ответственности, которую использует больше одной страницы. Внешний импорт из среза проходит через его `index.ts`; внутри среза применяются относительные импорты. Псевдоним `@/*` указывает на `src/*`.

Точка входа `main.tsx` остаётся тонкой и импортирует приложение из `app`. Провайдеры Mantine и маршрутизатора находятся в `app/providers`; таблица маршрутов находится в `app/routes`.

`SYSTEM.md` упоминает будущий клиент как `web/src/api`. При реализации запросов он должен находиться в `web/src/shared/api`, чтобы не создавать каталог вне слоёв FSD. В рамках этого изменения клиент не создаётся.

Альтернатива: сразу создать все стандартные слои FSD. Она даёт пустые каталоги и подталкивает к преждевременному разделению кода, поэтому не используется.

### 3. Команды проекта

`package.json` предоставляет:

- `dev`, `build` и `preview` для Vite;
- `typecheck` для TypeScript без генерации файлов;
- `lint:code` для Oxlint и `lint:fsd` для Steiger;
- `lint`, объединяющий обе проверки;
- `format` и `format:check` для Oxfmt;
- `check`, запускающий форматирование в режиме проверки, анализ, проверку типов и сборку.

Oxfmt не форматирует `.skills`, `.agents` и `.claude`, чтобы не менять загруженные инструкции сторонних проектов. Oxlint использует официальный `oxc-config-mantine` и проверяет React и TypeScript. Vite проксирует `/v1` на адрес из переменной окружения с безопасным локальным значением по умолчанию.

### 4. Подключение Mantine и Tailwind

Главный файл стилей задаёт порядок CSS-слоёв, подключает стили Mantine в отдельный слой, а затем Tailwind theme и utilities. `tailwindcss/preflight.css` не импортируется. Плагин `@tailwindcss/vite` обрабатывает Tailwind без отдельного `tailwind.config.js`.

Семантические CSS-переменные `--h3-*` являются общим нижним уровнем. Тема Mantine ссылается на них через палитры, virtual colors и собственный resolver вариантов. Tailwind получает отображение тех же переменных через `@theme inline`, поэтому оба способа оформления меняются синхронно при переключении `data-mantine-color-scheme`.

В приложение входят варианты `h3_accent`, `h3_secondary`, `h3_stroke` и `h3_ghost`. Типы Mantine дополняются именами вариантов, если этого требует API установленной версии.

### 5. Исправления доступности

Исходные токены нельзя переносить как неизменяемый снимок, потому что `design/quality/contrast-audit.md` фиксирует проблемы:

- светлое значение содержательного `h3_text_accent` меняется с `#51BA81` на `#1C7946`;
- для границ интерактивных элементов создаётся отдельный семантический токен со значениями не ниже 3:1 к соседнему фону;
- `h3_text_1` остаётся только у плейсхолдеров и неактивных элементов, содержательный вторичный текст использует `h3_text_2`;
- выбранное состояние сохраняет признак формы и не передаётся только цветом.

`web/DESIGN.md` перечисляет эти отличия от исходного снимка. Остальные числовые значения сохраняются, пока аудит не требует изменения.

### 6. Перенос каталога design

### 7. Канонические проектные навыки

Корневая `.skills/<skill-name>` хранит обычные файлы навыка. Пути `.agents/skills/<skill-name>` и `.claude/skills/<skill-name>` являются относительными символическими ссылками вида `../../.skills/<skill-name>`.

Существующий `humanizer` переносится без смысловых правок. Для OpenSpec за основу берутся текущие копии; их различия объединяются в нейтральный текст. Когда названия вызовов различаются, инструкция указывает оба варианта, например `$openspec-apply-change` для Codex и `/opsx:apply` для Claude. Команды из `.claude/commands/opsx` остаются на месте.

Официальный `feature-sliced-design` устанавливается целиком из `feature-sliced/skills` на ревизии `e7eac044ee7405b0e82abe8e54cab7a1e9e8bc0c`. Навыки `mantine-combobox`, `mantine-form` и `mantine-custom-components` устанавливаются целиком из `mantinedev/skills` на ревизии `222191c6b15d1ae2c02051a285f47230777be513`. Файл `.skills/SOURCES.md` хранит URL, ревизии и перечень импортированных каталогов.

Корневой `AGENTS.md` указывает канонический путь `humanizer`, вводит общее правило `.skills` и запрещает независимое редактирование файлов через пути отдельных агентов. Обновление сгенерированных навыков OpenSpec должно завершаться повторным объединением различий в `.skills` и восстановлением ссылок.

Альтернатива: хранить по полной копии для каждого агента. От неё отказываемся, потому что текущие OpenSpec-файлы уже разошлись в формулировках.

### 8. Локальные инструкции web

`web/CLAUDE.md` содержит только обязательную ссылку на `web/AGENTS.md`. `web/AGENTS.md` требует сначала прочитать `../AGENTS.md`, затем `DESIGN.md`, `feature-sliced-design/SKILL.md` и нужные для задачи навыки Mantine. Ссылки ведут на канонические файлы в `../.skills`, а не на агентские представления.

## Risks / Trade-offs

- [Символические ссылки могут быть отключены в рабочей среде] -> Проверить ссылки после создания и явно зафиксировать требование поддержки symlink в `AGENTS.md`.
- [Запуск `openspec update` может заменить ссылки целевыми копиями] -> Описать порядок повторного объединения и проверять, что в `.agents/skills` и `.claude/skills` не появились обычные каталоги общих навыков.
- [Mantine и Tailwind могут конкурировать за порядок CSS] -> Не подключать Preflight, использовать объявленный порядок слоёв и проверить штатную кнопку и поле Mantine в собранном приложении.
- [Миграция дизайн-документов может потерять частное правило] -> Сверить каждый исходный файл с инвентарём до удаления `design` и проверить ссылки в `web/DESIGN.md`.
- [Точная версия внешнего навыка устареет] -> Хранить источник и ревизию; обновлять каноническую копию отдельным осознанным изменением.
- [React Router 8 требует современный Node.js и React] -> Зафиксировать ожидаемые версии в `package.json`; текущая среда им соответствует.

## Migration Plan

1. Создать `.skills` и перенести туда `humanizer` и навыки OpenSpec, объединив только различающиеся ссылки на команды.
2. Заменить общие каталоги навыков в `.agents/skills` и `.claude/skills` относительными символическими ссылками; проверить каждую ссылку.
3. Скачать зафиксированные ревизии FSD и Mantine в `.skills`, добавить ссылки для обоих агентов и записать происхождение.
4. Обновить корневой `AGENTS.md`.
5. Создать каркас `web`, зависимости, настройки инструментов и минимальный маршрут.
6. Перенести тему и CSS-токены, подключить провайдеры и проверить обе цветовые схемы.
7. Собрать `web/DESIGN.md` по инвентарю, затем удалить `design`.
8. Создать `web/AGENTS.md` и `web/CLAUDE.md`.
9. Запустить `pnpm install --frozen-lockfile`, `pnpm check`, проверку символических ссылок и `openspec validate setup-web-frontend --strict`.

До начала переноса Git сохраняет исходные файлы, поэтому отдельный резервный каталог не нужен. Откат выполняется возвратом коммита изменения; пользовательские изменения в `SYSTEM.md` не затрагиваются.

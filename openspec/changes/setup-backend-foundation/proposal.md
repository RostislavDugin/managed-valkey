## Why

`SYSTEM.md` описывает API, оператор и их окружения, но в репозитории пока есть только frontend. Нужна воспроизводимая основа backend, на которой следующие изменения смогут реализовывать HTTP API, схему данных и reconcile без повторной настройки Go, контейнеров, миграций и локального кластера.

## What Changes

- Создать общий Go-модуль для `api`, `operator` и общего кода с закреплёнными версиями runtime-зависимостей и инструментов разработки.
- Создать запускаемые каркасы API на Gin и оператора на `controller-runtime`, общую настройку `slog`, проверки состояния и штатное завершение процессов.
- Взять каркас Kubernetes API, manager и контроллера из Kubebuilder, адаптировать его к структуре монорепозитория и сохранить воспроизводимую генерацию CRD, RBAC и DeepCopy. Начальный reconcile не управляет ресурсами до реализации поведения оператора отдельным изменением.
- Настроить `goose` для корневого каталога SQL-миграций, включая создание, применение и проверку миграций до запуска API.
- Добавить Dockerfile, `.golangci.yml` и локальный `Justfile` в каждый Go-каталог. API получает команды миграций, теста, линтинга, запуска и сборки; оператор получает быструю и полную проверки, линтинг, сборку и установку в dev k3s.
- Создать `docker-compose.dev.yml` с PostgreSQL, VictoriaLogs, трёхнодовым k3s, bootstrap, API и оператором.
- Создать `docker-compose.prod.yml` для Caddy, API, PostgreSQL, миграций и VictoriaLogs. Оператор продолжит разворачиваться в managed Kubernetes через `deploy/prod`.
- Добавить `.env.example`, Caddy и начальные манифесты `deploy`, необходимые для запуска окружений из `SYSTEM.md`.
- Создать локальные инструкции `api/AGENTS.md` и `operator/AGENTS.md`, а также символические ссылки `CLAUDE.md` на них. Правила Go адаптировать к ответственности каждого приложения.
- Оставить короткие `operator/TODO.md` и `e2e/TODO.md` с будущими сценариями восстановления primary и сквозной проверки через API, чтобы они не потерялись до реализации предметного поведения.
- Расширить `.githooks/pre-commit`: форматировать staged Go-файлы с возвратом в индекс, проверять линтером и собирать затронутые приложения; сохранить действующие проверки frontend.
- Обновить разделы `SYSTEM.md` о командах и структуре репозитория под локальные `Justfile` и корневые e2e-тесты, а в корневом `AGENTS.md` описать проверки Go перед коммитом.

## Capabilities

### New Capabilities

- `backend-foundation`: Общий Go-модуль, запускаемые процессы API и оператора, генерация Kubernetes-кода, логирование, проверки и команды разработки.
- `backend-environments`: Воспроизводимые dev- и prod-окружения с контейнерными образами, зависимостями запуска и конфигурацией из env.
- `database-migrations`: Управление схемой PostgreSQL через закреплённый `goose` и корневой каталог аддитивных SQL-миграций.

### Modified Capabilities

- `project-skill-layout`: Добавить цепочки локальных инструкций для `api` и `operator` по образцу существующей цепочки `web`.

## Impact

Изменение добавит корневые `go.mod`, `go.sum`, compose-файлы и `.env.example`; локальные `Justfile` и `.golangci.yml` в `api` и `operator`; новые каталоги `api`, `operator`, `internal`, `migrations`, `deploy`, `caddy` и `e2e`; локальные инструкции агентов. Изменятся `.githooks/pre-commit`, корневой `AGENTS.md` и разделы 14 и 16 `SYSTEM.md`. Появятся зависимости Gin, GORM, PostgreSQL, `controller-runtime`, Kubernetes client libraries, OpenTelemetry, `goose`, Air и инструменты генерации. Продуктовые обработчики API, таблицы предметной области и reconcile Valkey в этот каркас не входят.

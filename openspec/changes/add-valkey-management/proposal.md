## Why

После входа пользователь видит временную страницу без списка баз и рабочих
действий. Нужен первый законченный раздел консоли, на котором можно проверить
основной сценарий Managed Valkey до появления серверного API.

## What Changes

- Раздел Valkey с хлебными крошками «Базы данных» и адресуемыми вкладками
  «Управление», «Мониторинг» и «Аудит логи» внутри открытой базы. Первая вкладка
  работает полностью, две остальные показывают заглушки.
- Экран управления в композиции оригинального h3llo cloud: список баз с
  поиском и таблицей, отдельное пустое состояние, страница базы и правая панель
  стоимости там, где она нужна.
- Карточка базы с именем и быстрым переименованием, копируемым идентификатором,
  примерами подключения для JavaScript, TypeScript, Python и Go, а также
  постоянными статусом, меню удаления и панелью стоимости на всех вкладках.
- Создание, изменение имени и тарифа, удаление базы с подтверждением по имени.
- Выбор DNS-префикса при создании. Из него собирается неизменяемое DNS-имя базы
  `<префикс>-<6 случайных символов>`, как это делает `api` в `SYSTEM.md`.
- Выбор режима `single` или `ha` и любого допустимого сочетания vCPU и RAM из
  тарифной сетки `SYSTEM.md` с немедленным пересчётом цены.
- Загрузка и сохранение баз текущего пользователя через временный клиент над
  `localStorage`. Клиент повторяет асинхронные формы будущего API и скрывает
  хранилище от компонентов страниц.
- Стабильный `user_id` в сессии и записях Valkey. Временный auth переводит JWT
  `sub` с почты на идентификатор пользователя и мигрирует существующие данные
  браузера.
- Отображение занятой квоты при наличии баз. Недоступные тарифы остаются видны,
  а при нехватке квоты интерфейс предлагает обратиться в поддержку по адресу
  `https://t.me/rostislav_dugin`.
- Состояния загрузки, пустого списка, данных, ошибки и отсутствующей базы.

## Capabilities

### New Capabilities

- `web-valkey-management`: список и карточка базы с вкладками, крошки,
  создание, изменение, удаление, тарифы, квоты и временное хранение данных в
  браузере.

### Modified Capabilities

- `web-auth`: сессия получает `user_id`, JWT хранит его в `sub`, а временные
  аккаунты без идентификатора мигрируют при чтении.

## Impact

Код: новый срез `src/pages/valkey`, маршруты в `src/app/routes`, константы
маршрутов в `src/shared/config/routes.ts` и изменение временного auth-клиента
в `src/shared/api/auth.ts`. Клиент и модель Valkey остаются в срезе страницы,
пока ими пользуется только этот раздел. Текущая `HomePage` уступает место
экрану управления.

Данные браузера: новый ключ `localStorage` для баз Valkey. Записи связываются с
`user_id` из действующей сессии и сохраняются между перезагрузками. Существующие
записи `mv_users` без идентификатора и токены с почтой в `sub` получают
совместимую миграцию.

Дизайн: источники вне Git находятся в `/temp/h3llo-databases-list.png`,
`/temp/h3llo-databases-empty.png`, `/temp/h3llo-database-detail.png` и в
доступной через браузер странице h3llo cloud.
Новых зависимостей нет.

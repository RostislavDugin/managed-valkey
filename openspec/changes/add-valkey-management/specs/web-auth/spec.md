## MODIFIED Requirements

### Requirement: Сессия хранится в браузере

Признаком сессии SHALL быть токен в `localStorage` под ключом `mv_token`.
Токен SHALL содержать стабильный `user_id` в поле `sub` и разбираемый на
клиенте срок действия в поле `exp`. Объект сессии, доступный консоли, SHALL
возвращать `userId`, `email`, `expiresAt` и токен. Почта SHALL приходить из
данных аккаунта, а не служить идентификатором сессии.

Будущий API SHALL использовать UUIDv7 для `users.id` и передавать этот
идентификатор в `sub`. Серверной таблицы сессий нет, выход это удаление токена.

#### Scenario: Сессия переживает перезагрузку

- **WHEN** пользователь с действующим токеном перезагружает страницу
- **THEN** он остаётся в консоли и на той же странице
- **AND** консоль получает тот же `userId` из `sub`

#### Scenario: Ресурс связывается с пользователем

- **WHEN** консоль создаёт ресурс от имени действующей сессии
- **THEN** владельцем служит `userId`, полученный из JWT `sub`
- **AND** почта не используется как идентификатор владельца

#### Scenario: Выход по кнопке

- **WHEN** пользователь нажимает «Выйти»
- **THEN** `mv_token` удаляется
- **AND** открывается `/auth` на первом шаге

### Requirement: Временная реализация без сервера

До появления `api` вход SHALL работать поверх `localStorage`, повторяя формы
запросов и ответов `/v1/auth/*` и коды ошибок. Реализация SHALL быть заперта за
одним модулем клиента: страницы и оболочка о хранилище знать MUST NOT.

Аккаунты хранятся под ключом `mv_users`, пароли открытым текстом. Каждая запись
аккаунта SHALL иметь стабильный `id` в формате UUIDv7. Временный JWT SHALL
хранить этот идентификатор в `sub`. Ключ `mv_users` исчезает вместе с этой
реализацией, ключ `mv_token` остаётся и принимает JWT.

#### Scenario: Замена на api

- **WHEN** появляется настоящий `api`
- **THEN** меняется только тело модуля клиента
- **AND** страницы, маршруты и оболочка правок не требуют

#### Scenario: Регистрация временного аккаунта

- **WHEN** временный клиент регистрирует новый аккаунт
- **THEN** он сохраняет аккаунту новый UUIDv7
- **AND** возвращённый токен содержит этот идентификатор в `sub`

#### Scenario: Миграция существующего аккаунта

- **WHEN** временный клиент читает запись `mv_users` без `id`
- **THEN** он назначает записи UUIDv7 и сохраняет обновлённый список
- **AND** почта и пароль аккаунта остаются прежними

#### Scenario: Миграция существующей сессии

- **WHEN** действующий временный токен содержит почту в `sub`
- **THEN** клиент находит аккаунт по нормализованной почте
- **AND** заменяет токен версией с `user_id` в `sub` и прежним `exp`

#### Scenario: Старый токен не связан с аккаунтом

- **WHEN** временный токен с почтой в `sub` нельзя связать с записью `mv_users`
- **THEN** клиент удаляет токен как недействительный

#### Scenario: Видимость демонстрационного режима

- **WHEN** открыт экран входа во временной реализации
- **THEN** под формой видна пометка, что данные хранятся в браузере
- **AND** пометка исчезает вместе с временной реализацией

#### Scenario: Задержка ответа

- **WHEN** экран обращается к временной реализации
- **THEN** ответ приходит с задержкой, сравнимой с сетевой
- **AND** индикаторы загрузки успевают отобразиться

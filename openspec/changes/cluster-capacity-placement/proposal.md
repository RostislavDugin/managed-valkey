## Why

В рабочем окружении появился управляемый кластер Kubernetes из трёх нод по 4 vCPU и 16 GiB, но CI/CD пока доставляет только сервисы `Docker Compose` и оставляет синхронизацию API выключенной. API проверяет общую квоту, однако не проверяет, можно ли распределить зарезервированные процессы по отдельным нодам.

## What Changes

- Подключить Kubernetes рабочего окружения к выпуску: CRD, права API и оператора, оператор, Envoy Gateway и подключение API с отдельными правами.
- Хранить файл подключения к Kubernetes для развёртывания в секретах окружения GitHub `production`; исключить административные учётные данные из контейнера API.
- **BREAKING**: заменить двусмысленные настройки общей ёмкости `MANAGED_K8S_NODE_*` явными настройками количества нод, физических ресурсов ноды и резерва инфраструктуры. Общую квоту вычислять из доступного Valkey бюджета каждой ноды.
- Проверять возможность размещения всех резервов: `single` занимает одну ноду, три процесса HA занимают разные ноды. Учитывать CPU и RAM одновременно, изменение размера, неподтверждённое удаление и конкурентные запросы.
- Сохранить `422 NOT_ENOUGH_RESOURCES`; добавить `details.reason=placement_capacity` для невозможности размещения при достаточном общем бюджете.
- Дополнить тесты только в `api/`. Не расширять `tests/integrations`, сквозные тесты Playwright и тесты оператора.
- Публиковать образ оператора в общедоступном пакете `ghcr.io/rostislavdugin/managed-valkey-operator` с тегом, равным SHA коммита. Кластер скачивает образ без `imagePullSecrets`; оператор остаётся внутри Kubernetes.

## Capabilities

### New Capabilities

- `api-cluster-placement`: конфигурация топологии, расчёт размещения резервов и причины отказа.

### Modified Capabilities

- `api-valkey-quotas`: вычисление общей квоты из топологии и дополнительная проверка размещения при создании и изменении размера.
- `ci-cd`: доставка компонентов в Kubernetes рабочего окружения и включение синхронизации API после подготовки кластера.

## Impact

Изменятся конфигурация и сервисы API, расчёт резервов и тесты `api/`, конфигурация `Docker Compose` рабочего окружения, процесс CI/CD, сценарий установки выпуска и `deploy/prod`. Документация конфигурации должна описывать реальный смысл бюджета. Kubernetes CRD `ValkeyInstance` и логика оператора не получают указаний размещать `Pod` на конкретной ноде: API проверяет расчётную вместимость, фактическое размещение остаётся за Kubernetes.

Для запуска потребуются секреты подключения, общедоступный пакет образа оператора, внешний адрес Envoy и TLS для домена Valkey. Точные резервы инфраструктуры требуют решения до выкладки в рабочее окружение; создание этих файлов не разворачивает инфраструктуру.

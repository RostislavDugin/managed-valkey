# web-valkey-management

## Purpose

Раздел Valkey позволяет управлять базами, тарифами и занятой квотой до подключения серверного API, сохраняя рабочие сценарии в браузере.

## Requirements

### Requirement: Вкладки принадлежат открытой базе

Вкладки «Управление», «Мониторинг» и «Аудит» SHALL показываться только на
странице конкретной базы. Каждая вкладка SHALL иметь собственный адрес внутри
адреса базы, сохраняться при перезагрузке и подходить для прямой ссылки.
Список баз, пустое состояние и форма создания вкладки показывать MUST NOT.

#### Scenario: Открытие раздела Valkey

- **WHEN** пользователь открывает раздел Valkey без адреса конкретной базы
- **THEN** консоль показывает список баз или пустое состояние
- **AND** вкладок на странице нет

#### Scenario: Открытие формы создания

- **WHEN** пользователь открывает форму создания базы
- **THEN** вкладок на странице нет

#### Scenario: Открытие вкладки по прямой ссылке

- **WHEN** пользователь открывает прямую ссылку на «Мониторинг» или «Аудит» базы
- **THEN** консоль открывает эту базу с указанной вкладкой
- **AND** перезагрузка не возвращает пользователя на «Управление»

#### Scenario: Заглушка мониторинга

- **WHEN** пользователь выбирает вкладку «Мониторинг» открытой базы
- **THEN** консоль показывает метрики этой базы

#### Scenario: Заглушка журнала аудита

- **WHEN** пользователь выбирает вкладку «Аудит» открытой базы
- **THEN** консоль показывает журнал действий с этой базой

### Requirement: Раздел раскладывается по каркасу консоли

Хлебные крошки SHALL стоять в шапке консоли, а не в содержимом страницы. Правая
панель SHALL быть колонкой каркаса у правого края окна, а не карточкой внутри
контейнера страницы. Страница без постоянного контекста колонку показывать
MUST NOT, и пустая колонка ширину контента занимать MUST NOT. Ниже ширины
1280px правая панель SHALL открываться выдвижным блоком по кнопке.

#### Scenario: Место хлебных крошек

- **WHEN** открыта любая страница раздела
- **THEN** крошки стоят в шапке консоли, вне содержимого страницы

#### Scenario: Панель расчёта в форме создания

- **WHEN** пользователь открывает форму создания на ширине от 1280px
- **THEN** расчёт стоимости стоит в правой колонке консоли
- **AND** переключатель периода стоит в её верхней строке

#### Scenario: Панель использования в списке

- **WHEN** открыт непустой список баз на ширине от 1280px
- **THEN** занятая квота стоит в правой колонке консоли

#### Scenario: Единое оформление подписей формы

- **WHEN** открыта форма создания
- **THEN** подписи режима, vCPU, RAM, имени и префикса набраны одним кеглем и начертанием
- **AND** у каждой стоит иконка подсказки

#### Scenario: Выбранная карточка режима

- **WHEN** пользователь выбирает режим
- **THEN** его карточка получает акцентную рамку и подложку

#### Scenario: Раздел без правой панели

- **WHEN** открыта страница без постоянного контекста
- **THEN** правой колонки нет
- **AND** содержимое занимает всю ширину

### Requirement: Хлебные крошки называют раздел и открытую базу

Каждая страница раздела SHALL показывать хлебные крошки. Первая крошка SHALL
называться «Базы данных» и вести к списку баз.

#### Scenario: Список баз

- **WHEN** открыт список баз или пустое состояние
- **THEN** крошки состоят из одной «Базы данных» без разделителя

#### Scenario: Создание базы

- **WHEN** открыта форма создания
- **THEN** крошки читаются как «Базы данных / Создание БД»

#### Scenario: Страница базы

- **WHEN** открыта база `valkey-1474` на любой из своих вкладок
- **THEN** крошки читаются как «Базы данных / valkey-1474»

### Requirement: Управление загружает сохранённые базы пользователя

Вкладка «Управление» SHALL загружать базы вошедшего пользователя при каждом
открытии. Базы другого аккаунта в том же браузере показываться MUST NOT.

#### Scenario: Повторное открытие списка

- **WHEN** пользователь создал базу и позднее снова открыл вкладку «Управление»
- **THEN** ранее созданная база присутствует в списке с сохранёнными параметрами

#### Scenario: Смена аккаунта

- **WHEN** в том же браузере входит другой пользователь
- **THEN** он видит только базы, у которых владелец совпадает с его `user_id`

#### Scenario: Загрузка данных

- **WHEN** вкладка «Управление» получает сохранённые базы
- **THEN** консоль резервирует место под содержимое и показывает состояние загрузки
- **AND** список появляется после завершения запроса

### Requirement: Список баз повторяет композицию h3llo cloud

При наличии баз вкладка «Управление» SHALL показывать заголовок Valkey,
кнопку создания, поиск, таблицу и правую панель занятой квоты. Таблица SHALL
содержать имя, статус, режим, vCPU, RAM, цену за месяц и меню действий.

#### Scenario: Список с данными

- **WHEN** загрузка возвращает хотя бы одну базу
- **THEN** каждая база отображается отдельной строкой таблицы
- **AND** нажатие на имя открывает страницу этой базы

#### Scenario: Поиск по базам

- **WHEN** пользователь вводит текст в поиск
- **THEN** таблица оставляет базы, у которых текст встречается в имени, DNS-имени, статусе, режиме или тарифе без учёта регистра

#### Scenario: Поиск ничего не нашёл

- **WHEN** ни одна сохранённая база не соответствует строке поиска
- **THEN** таблица показывает сообщение «Ничего не найдено»
- **AND** состояние не подменяется экраном, предназначенным для аккаунта без баз

### Requirement: Пустой список даёт точку входа в создание

Аккаунт без баз SHALL видеть отдельное пустое состояние с названием Valkey,
кратким описанием управляемой базы и кнопкой «Создать базу».

#### Scenario: У пользователя нет баз

- **WHEN** загрузка возвращает пустой список
- **THEN** консоль показывает пустое состояние вместо таблицы и панели квоты
- **AND** кнопка «Создать базу» открывает форму создания

### Requirement: Пользователь может создать базу Valkey

Форма создания SHALL запрашивать имя, префикс, режим `single` или `ha` и тариф.
При открытии форма SHALL выбрать рабочие значения по умолчанию, если квота
допускает хотя бы один тариф.

#### Scenario: Рабочая форма по умолчанию

- **WHEN** пользователь открывает форму и доступен хотя бы один тариф
- **THEN** форма содержит сгенерированное имя вида `valkey-1474`
- **AND** выбраны префикс `valkey`, режим `single` и первый доступный тариф
- **AND** кнопку «Создать базу» можно нажать без дополнительного ввода

#### Scenario: Успешное создание

- **WHEN** пользователь отправляет допустимую конфигурацию в пределах квоты
- **THEN** консоль сохраняет новую базу для текущего аккаунта
- **AND** открывает страницу созданной базы
- **AND** база остаётся доступна после перезагрузки

#### Scenario: Имя уже занято

- **WHEN** у текущего пользователя уже есть база с таким именем
- **THEN** новая база не создаётся
- **AND** у поля имени появляется сообщение «База с таким именем уже существует»

#### Scenario: Имя не прошло проверку

- **WHEN** имя содержит что-либо кроме строчных латинских букв, цифр и дефиса либо начинается или заканчивается дефисом
- **THEN** форма не отправляется
- **AND** ошибка стоит у поля имени

### Requirement: База получает DNS-имя из префикса

Префикс SHALL запрашиваться отдельно от имени и содержать от 3 до 20 символов
из строчных латинских букв, цифр и дефиса, начинаясь и заканчиваясь буквой или
цифрой. При создании консоль SHALL собирать DNS-имя базы как
`<префикс>-<6 случайных символов [a-z0-9]>` и подбирать другое при совпадении с
занятым. DNS-имя SHALL быть уникальным среди всех баз, а не только баз одного
владельца, и после создания меняться MUST NOT.

#### Scenario: Префикс по умолчанию

- **WHEN** пользователь открывает форму создания
- **THEN** в поле префикса стоит `valkey`
- **AND** рядом виден будущий адрес базы с шестью случайными символами и доменом инстансов

#### Scenario: Домен недоступен

- **WHEN** запрос домена инстансов не удался
- **THEN** форма открывается как обычно
- **AND** подсказка показывает DNS-имя без домена

#### Scenario: Префикс не прошёл проверку

- **WHEN** префикс короче 3 или длиннее 20 символов, содержит другие символы либо начинается или заканчивается дефисом
- **THEN** форма не отправляется
- **AND** ошибка стоит у поля префикса

#### Scenario: DNS-имя созданной базы

- **WHEN** пользователь создаёт базу с префиксом `shop`
- **THEN** у базы появляется DNS-имя вида `shop-a1b2c3`
- **AND** страница базы показывает адрес `shop-a1b2c3.<домен>:<порт>`

#### Scenario: Совпадение DNS-имён

- **WHEN** случайная часть повторяет занятое DNS-имя
- **THEN** консоль подбирает другую

#### Scenario: Переименование не трогает DNS-имя

- **WHEN** пользователь меняет имя базы
- **THEN** DNS-имя остаётся прежним

### Requirement: Тариф показывает ресурсы и стоимость

Консоль SHALL предлагать готовые конфигурации из примеров `SYSTEM.md`: `1/1`,
`1/2`, `1/4`, `2/4`, `2/8` и `4/16`, где первое число это vCPU, второе RAM в
ГБ. Каждая конфигурация SHALL показывать ресурсы и месячную цену в одной
радио-карточке.

Режим `single` SHALL использовать одну ноду, режим `ha` три ноды. Форма SHALL
показывать ресурсы на ноду и суммарный расход. Значения, которые не помещаются
в текущую квоту, SHALL оставаться доступными для просмотра цены.

Стоимость одной ноды в час SHALL вычисляться как
`1,25 ₽ * vCPU + 0,50 ₽ * RAM в ГБ`. Цена базы SHALL учитывать число нод.
Месяц SHALL равняться 720 часам,
день 24 часам.

#### Scenario: Смена тарифа

- **WHEN** пользователь выбирает другой размер
- **THEN** панель стоимости сразу пересчитывает цену за выбранный период
- **AND** показывает выбранные vCPU и RAM

#### Scenario: Доступны готовые конфигурации

- **WHEN** пользователь открывает выбор тарифа
- **THEN** он выбирает vCPU и RAM одной карточкой
- **AND** карточка показывает месячную цену и доступность по квоте

#### Scenario: Смена режима при создании

- **WHEN** пользователь меняет режим с `single` на `ha`
- **THEN** суммарные ресурсы и цена увеличиваются в три раза
- **AND** ресурсы на одну ноду остаются прежними

#### Scenario: Смена периода цены

- **WHEN** пользователь выбирает «Месяц», «День» или «Час»
- **THEN** итог отображается для 720, 24 или одного часа соответственно

### Requirement: Квота ограничивает создание и изменение тарифа

Квота пользователя SHALL составлять 4 vCPU и 16 ГБ RAM. Занятые ресурсы SHALL
считаться как сумма `число нод * размер ноды` по всем базам пользователя.

#### Scenario: Использование квоты видно при наличии баз

- **WHEN** у пользователя есть хотя бы одна база
- **THEN** правая панель списка показывает занятые и доступные vCPU и RAM

#### Scenario: У пользователя нет баз

- **WHEN** список баз пуст
- **THEN** сведения о занятой квоте не показываются

#### Scenario: Тариф превышает остаток квоты

- **WHEN** суммарные ресурсы выбранного тарифа не помещаются в остаток квоты
- **THEN** тариф остаётся видимым и его цену можно посмотреть, но отправить форму нельзя
- **AND** рядом указано, какого ресурса не хватает
- **AND** консоль предлагает написать в поддержку для увеличения квоты со ссылкой на `https://t.me/rostislav_dugin`

#### Scenario: Доступного тарифа нет

- **WHEN** оставшейся квоты не хватает ни на один тариф
- **THEN** отправка формы недоступна
- **AND** консоль предлагает написать в поддержку для увеличения квоты
- **AND** ссылка ведёт на `https://t.me/rostislav_dugin`

#### Scenario: Проверка квоты при изменении

- **WHEN** пользователь меняет тариф существующей базы
- **THEN** консоль исключает текущий размер этой базы из занятой квоты перед проверкой нового размера

### Requirement: Страница базы поддерживает изменение

Каждая база SHALL иметь отдельный адрес. Страница SHALL показывать имя, адрес
подключения с доменом и портом, статус, режим, текущий тариф, суммарные ресурсы
и цену, а также действия изменения и удаления.

#### Scenario: Постоянный каркас страницы базы

- **WHEN** пользователь переходит между управлением, мониторингом и журналом аудита
- **THEN** статус и меню удаления остаются справа в шапке
- **AND** правая панель текущей стоимости остаётся заполненной
- **AND** левый отступ вкладок и содержимого не меняется

#### Scenario: Имя и идентификатор

- **WHEN** пользователь открывает вкладку управления
- **THEN** первым заголовком показано имя базы с кнопкой переименования
- **AND** ниже показаны тип `Valkey`, полный идентификатор базы и действие копирования
- **AND** вкладки базы расположены под идентификатором и над содержимым раздела

#### Scenario: Примеры подключения

- **WHEN** пользователь открывает вкладку управления
- **THEN** он может выбрать пример для JavaScript, TypeScript, Python или Go
- **AND** скопировать активный пример
- **AND** пример содержит адрес и порт базы, пользователя `app`, TLS и заполнитель `<PASSWORD>`

#### Scenario: Выбор нового тарифа

- **WHEN** пользователь открывает изменение тарифа
- **THEN** он выбирает конфигурацию из радио-карточек
- **AND** текущая конфигурация доступна для выбора, даже если её нет среди стандартных карточек
- **AND** пояснение с ресурсами на ноду и суммарными ресурсами не показывается

#### Scenario: Открытие базы

- **WHEN** пользователь выбирает базу в таблице
- **THEN** открывается её страница с сохранёнными параметрами
- **AND** вкладка «Управление» остаётся выбранной

#### Scenario: Изменение имени и тарифа

- **WHEN** пользователь сохраняет допустимое свободное имя и доступный тариф
- **THEN** консоль обновляет базу
- **AND** новые значения появляются в карточке и списке после перезагрузки

#### Scenario: Ресайз базы single

- **WHEN** пользователь меняет размер базы в режиме `single`
- **THEN** перед сохранением консоль предупреждает о простое и полной очистке кеша
- **AND** сообщает, что ресайз нельзя отменить после принятия

#### Scenario: Уменьшение RAM базы ha

- **WHEN** пользователь уменьшает RAM базы в режиме `ha`
- **THEN** перед сохранением консоль предупреждает о полной очистке кеша
- **AND** сообщает, что новый тариф действует с момента принятия ресайза

#### Scenario: Другой ресайз базы ha

- **WHEN** пользователь меняет vCPU или увеличивает RAM базы в режиме `ha`
- **THEN** перед сохранением консоль предупреждает о возможной потере последних записей при смене primary
- **AND** сообщает, что ресайз нельзя отменить после принятия

#### Scenario: Режим нельзя изменить после создания

- **WHEN** пользователь изменяет существующую базу
- **THEN** режим отображается как неизменяемое свойство

#### Scenario: База не найдена

- **WHEN** адрес содержит неизвестный идентификатор базы
- **THEN** консоль сообщает, что база не найдена
- **AND** предлагает вернуться к списку

### Requirement: Удаление требует подтверждения

Удаление SHALL запрашивать подтверждение с точным именем базы. До подтверждения
данные меняться MUST NOT.

#### Scenario: Подтверждение удаления

- **WHEN** пользователь выбирает удаление базы `valkey-1474`
- **THEN** окно задаёт вопрос «Удалить базу `valkey-1474`?»
- **AND** основная кнопка окна называется «Удалить базу»

#### Scenario: Отмена удаления

- **WHEN** пользователь закрывает подтверждение или нажимает «Отмена»
- **THEN** база остаётся в хранилище и списке

#### Scenario: Успешное удаление

- **WHEN** пользователь подтверждает удаление
- **THEN** база исчезает из списка и больше не занимает квоту
- **AND** после удаления последней базы появляется пустое состояние

### Requirement: Временный клиент имитирует API через localStorage

До появления API операции списка, чтения, создания, изменения и удаления SHALL
работать через `localStorage` с задержкой, достаточной для отображения состояний
загрузки. Домен и порт инстансов SHALL приходить из клиента запросом, а не
записываться в компоненты константой. Каждая база SHALL хранить владельца по `user_id` из действующей
сессии. Компоненты страниц MUST NOT обращаться к `localStorage` напрямую.

#### Scenario: Домен инстансов

- **WHEN** страница запрашивает домен инстансов
- **THEN** клиент отдаёт значения `VALKEY_BASE_DOMAIN` и `VALKEY_PUBLIC_PORT`
- **AND** без переменных окружения отдаёт значения прода

#### Scenario: Замена временного клиента

- **WHEN** появляется серверный API с теми же формами запросов и ответов
- **THEN** хранение можно заменить внутри клиента без изменения компонентов форм и страниц

#### Scenario: Хранилище браузера недоступно

- **WHEN** браузер не позволяет прочитать или записать данные
- **THEN** консоль показывает понятное сообщение об ошибке
- **AND** предлагает повторить операцию

#### Scenario: Запись без DNS-имени

- **WHEN** в хранилище лежит документ предыдущей версии, где у баз нет префикса и DNS-имени
- **THEN** клиент берёт префикс из имени базы и выдаёт ей DNS-имя
- **AND** остальные поля базы остаются прежними

#### Scenario: Повреждённые данные

- **WHEN** сохранённое значение не соответствует ожидаемому формату
- **THEN** консоль не выполняет действие над непроверенными данными
- **AND** показывает ошибку загрузки с возможностью повтора

### Requirement: Создание базы выдаёт пароль Valkey один раз

Перед отправкой формы создания консоль SHALL сгенерировать пароль пользователя
Valkey `app` из 24 случайных байт криптографического генератора и закодировать
его как 32 символа base64url без padding. Пользователь MUST NOT задавать этот
пароль вручную. После принятия создания консоль SHALL открыть вкладку
«Управление» созданной базы и один раз показать полный пароль.

#### Scenario: База успешно создана

- **WHEN** временный клиент принимает создание базы
- **THEN** консоль открывает вкладку «Управление» созданной базы
- **AND** показывает полный пароль в окне с кнопкой копирования
- **AND** предупреждает, что после закрытия окна пароль нельзя посмотреть снова
- **AND** не показывает статус «Готов» или другую служебную готовность

#### Scenario: Создание не принято

- **WHEN** временный клиент отклоняет создание базы
- **THEN** полный пароль не показывается
- **AND** повторная отправка исправленной формы получает новый пароль

### Requirement: Управление показывает учётные данные Valkey

Вкладка «Управление» SHALL показывать пользователя `app` и маску текущего пароля
вида `jz3f*****`. Пока новый пароль применяется, рядом с маской SHALL быть
показано состояние операции. Полный текущий пароль SHALL отсутствовать в
обычном ответе и на странице.

#### Scenario: Текущий пароль применён

- **WHEN** применённая версия пароля равна текущей версии
- **THEN** рядом с маской нет отдельного статуса
- **AND** действие «Сменить пароль» доступно для работающей базы

#### Scenario: Новый пароль применяется

- **WHEN** применённая версия пароля меньше текущей версии
- **THEN** рядом с маской показано состояние «Применяется»
- **AND** повторная смена пароля недоступна до завершения операции

#### Scenario: Учётные данные не загрузились

- **WHEN** запрос учётных данных завершился ошибкой
- **THEN** вкладка сообщает причину рядом с блоком учётных данных
- **AND** предлагает повторить запрос, не скрывая остальное содержимое вкладки

#### Scenario: Значения в блоке управления оформлены единообразно

- **WHEN** вкладка «Управление» показывает свойства базы
- **THEN** значения справа используют одинаковый обычный нежирный шрифт и серый цвет
- **AND** адрес использует моноширинный шрифт
- **AND** действия «Сменить» и «Изменить» имеют размер и обычное начертание подписей, сохраняя зелёный цвет

### Requirement: Пользователь может сменить пароль Valkey

Смена пароля SHALL быть доступна для базы в состоянии `running` или `degraded`
при свежем наблюдении, завершённом предыдущем изменении конфигурации и без
запрошенного удаления. Консоль SHALL генерировать пароль по тем же правилам,
что при создании, и отправлять ожидаемую текущую версию. Собственный пароль
пользователя MUST NOT приниматься.

#### Scenario: Подтверждение смены пароля

- **WHEN** пользователь выбирает действие «Сменить пароль»
- **THEN** окно предупреждает «Все подключения Valkey будут закрыты. Обновите пароль в приложениях»
- **AND** пароль не генерируется и запрос не отправляется до подтверждения

#### Scenario: Смена пароля принята

- **WHEN** пользователь подтверждает смену и временный клиент принимает запрос
- **THEN** версия пароля увеличивается
- **AND** окно один раз показывает полный новый пароль и кнопку копирования
- **AND** новый пароль подписан состоянием «Применяется», пока его версия не подтверждена

#### Scenario: Смена пароля у базы degraded

- **WHEN** пользователь меняет пароль базы в состоянии `degraded`
- **THEN** подтверждение сообщает, что недоступный прежний процесс может задержать применение

#### Scenario: Версия пароля изменилась до отправки

- **WHEN** временный клиент отклоняет запрос из-за несовпадения ожидаемой версии
- **THEN** консоль не показывает сгенерированный пароль как принятый
- **AND** заново загружает учётные данные и предлагает повторить действие

#### Scenario: Предыдущее изменение ещё выполняется

- **WHEN** база уже применяет размер, белый список или пароль
- **THEN** действие смены пароля недоступно
- **AND** вкладка объясняет, что сначала нужно дождаться текущей операции

### Requirement: Полный пароль живёт только до закрытия одноразового окна

Полный пароль SHALL храниться только в памяти страницы до завершения текущего
одноразового показа. Он MUST NOT попадать в `localStorage`, `sessionStorage`,
IndexedDB, URL, состояние и историю маршрутов, уведомления, журнал аудита или
аналитику.

#### Scenario: Пользователь закрывает окно

- **WHEN** пользователь закрывает окно с полным паролем
- **THEN** консоль удаляет пароль из своего состояния
- **AND** повторное открытие действия показывает только маску

#### Scenario: Пользователь покидает вкладку управления

- **WHEN** пользователь переходит на другой маршрут, перезагружает страницу или браузер отправляет `pagehide`
- **THEN** полный пароль удаляется из состояния
- **AND** возврат из bfcache не восстанавливает одноразовое окно

#### Scenario: Ответ пришёл после закрытия окна

- **WHEN** пользователь закрыл ожидающее окно до завершения запроса, а ответ пришёл позднее
- **THEN** консоль не открывает окно с паролем заново

#### Scenario: Пользователь копирует пароль

- **WHEN** пользователь нажимает кнопку копирования в одноразовом окне
- **THEN** консоль записывает полный пароль в буфер обмена
- **AND** без этого действия консоль не обращается к буферу обмена

#### Scenario: Страница перезагружена во время применения

- **WHEN** пароль потерян из памяти после перезагрузки, а его версия ещё применяется
- **THEN** вкладка показывает состояние «Применяется» без полного пароля
- **AND** получить этот пароль повторно нельзя

### Requirement: Смена пароля попадает в аудит без секрета

Успешно принятая смена пароля SHALL добавить одно событие
`instance.password.rotate` с автором и временем. Полный пароль, его маска и тело
запроса MUST NOT входить в событие.

#### Scenario: Смена пароля принята

- **WHEN** временный клиент успешно принимает смену пароля
- **THEN** журнал базы получает одно событие `instance.password.rotate`
- **AND** русская подпись события читается как «Изменён пароль»

#### Scenario: Смена пароля отклонена

- **WHEN** проверка запроса завершается ошибкой до записи новой версии
- **THEN** журнал не получает событие смены пароля

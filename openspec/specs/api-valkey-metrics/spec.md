# api-valkey-metrics

## Purpose

API хранит снимки метрик нод Valkey и отдаёт ограниченные по размеру временные ряды только владельцу выбранной базы.

## Requirements

### Requirement: PostgreSQL хранит снимки метрик нод

Схема PostgreSQL SHALL содержать таблицу `valkey_node_metrics` с полями `instance_id`, `ordinal`, `ts`, `role`, `run_id`, `used_memory_bytes`, `maxmemory_bytes`, `connected_clients`, `ops_per_sec`, `keyspace_hits`, `keyspace_misses`, `evicted_keys` и допускающим `null` полем `cpu_millicores`. Таблица SHALL связывать строку с `valkey_instances`, принимать только неотрицательные числовые значения и роли `primary`, `replica` или `unknown`. Пара `(instance_id, ordinal, ts)` SHALL быть уникальной, а выборка по `(instance_id, ts DESC)` SHALL поддерживаться отдельным индексом.

#### Scenario: Сохранение полного снимка

- **WHEN** в таблицу записывают снимок с известным CPU
- **THEN** PostgreSQL сохраняет все поля с исходным временем `ts` до микросекунд

#### Scenario: CPU отсутствует

- **WHEN** снимок содержит `cpu_millicores = null`
- **THEN** PostgreSQL принимает снимок без подстановки нуля

#### Scenario: Повторный снимок

- **WHEN** для той же базы, ноды и времени уже существует строка
- **THEN** ограничение уникальности не допускает вторую строку

### Requirement: API принимает фиксированное или произвольное окно

`GET /v1/managed/valkey/instances/{id}/metrics` SHALL принимать либо `range` со значением `5m`, `1h`, `24h` или `7d`, либо пару времён `from` и `to` в формате RFC 3339. При отсутствии параметров API SHALL использовать `range=1h`. Пара `from` и `to` SHALL задавать полуинтервал `[from, to)`, где `from < to` и ширина не превышает 7 дней. `range` MUST NOT передаваться вместе с `from` или `to`; неполная пара, неизвестный параметр и неверное значение SHALL возвращать `400 VALIDATION_FAILED`.

#### Scenario: Окно по умолчанию

- **WHEN** владелец запрашивает метрики без параметров
- **THEN** API возвращает последний час метрик

#### Scenario: Фиксированное окно

- **WHEN** владелец передаёт одно из значений `range`
- **THEN** API использует соответствующие ширину окна и шаг агрегации

#### Scenario: Произвольное окно

- **WHEN** владелец передаёт корректные `from` и `to` шириной не более 7 дней
- **THEN** API возвращает метрики из полуинтервала `[from, to)`

#### Scenario: Несовместимые параметры

- **WHEN** запрос одновременно содержит `range` и пару `from`, `to`
- **THEN** API возвращает `400 VALIDATION_FAILED`

#### Scenario: Слишком широкое окно

- **WHEN** разница между `from` и `to` превышает 7 дней
- **THEN** API возвращает `400 VALIDATION_FAILED`

### Requirement: API ограничивает число точек агрегацией

API SHALL использовать шаг 10 секунд для окна до 5 минут, 1 минуту для окна до 1 часа, 5 минут для окна до 24 часов и 30 минут для окна до 7 дней. Ответ для фиксированных окон `5m`, `1h`, `24h` и `7d` SHALL содержать соответственно не более 30, 60, 288 и 336 точек на ноду. Точки SHALL идти по времени от старых к новым, а ноды SHALL идти по `ordinal`.

#### Scenario: Пять минут

- **WHEN** клиент запрашивает `range=5m`
- **THEN** API возвращает шаг 10 секунд и не более 30 точек на ноду

#### Scenario: Семь дней

- **WHEN** клиент запрашивает `range=7d`
- **THEN** API возвращает шаг 30 минут и не более 336 точек на ноду

#### Scenario: Произвольное окно между готовыми диапазонами

- **WHEN** ширина пары `from`, `to` больше 1 часа и не больше 24 часов
- **THEN** API использует шаг 5 минут

### Requirement: API агрегирует метрики без заполнения пропусков

В каждой временной корзине API SHALL считать среднее доступных `used_memory_bytes`, `connected_clients`, `ops_per_sec` и `cpu_millicores`. Для `keyspace_hits`, `keyspace_misses` и `evicted_keys` API SHALL возвращать прирост за корзину. Прирост SHALL считаться между соседними снимками одного `run_id`; первый снимок нового `run_id` SHALL давать своё значение без вычитания снимка прежнего процесса. Корзина без снимков SHALL содержать `null` для всех метрик, а корзина без CPU SHALL содержать `cpu_millicores = null`. API MUST NOT интерполировать значения или заменять пропуски нулями.

#### Scenario: Несколько снимков в корзине

- **WHEN** одна корзина содержит несколько снимков одной ноды
- **THEN** API возвращает средние значения памяти, подключений, операций и доступных значений CPU

#### Scenario: Перезапуск процесса

- **WHEN** соседние снимки содержат разные `run_id`
- **THEN** прирост счётчиков для нового процесса равен значению его первого снимка

#### Scenario: Пустая корзина

- **WHEN** между двумя корзинами с данными нет снимка
- **THEN** ответ содержит промежуточную точку со значениями `null`

#### Scenario: Нет значения CPU

- **WHEN** в корзине есть снимки, но у всех `cpu_millicores = null`
- **THEN** остальные метрики агрегируются, а CPU остаётся `null`

### Requirement: API возвращает отдельный ряд для каждой ноды

Успешный ответ SHALL содержать `from`, `to`, `step_seconds` и массив `nodes`. Каждая нода SHALL содержать `ordinal`, имя `<slug>-<ordinal>`, последнюю известную в окне роль и массив `points`. Каждая точка SHALL содержать время начала корзины в `collected_at`, средние показатели и приросты счётчиков. Нода без снимков в выбранном окне MUST NOT появляться в ответе. API MUST NOT возвращать `run_id` или создавать демонстрационные метрики.

#### Scenario: Метрики одной ноды

- **WHEN** выбранное окно содержит снимки только ноды с `ordinal=0`
- **THEN** ответ содержит один ряд с её именем, ролью и точками

#### Scenario: Роль изменилась

- **WHEN** роль ноды менялась внутри окна
- **THEN** ряд содержит роль из последнего снимка этой ноды в окне

#### Scenario: Метрик пока нет

- **WHEN** в выбранном окне нет сохранённых снимков
- **THEN** API возвращает `200` и пустой массив `nodes`

### Requirement: Метрики доступны только владельцу базы

Путь метрик SHALL использовать общую проверку владельца для `/v1/managed/valkey/instances/{id}`. Запрос без действующего JWT SHALL возвращать `401 UNAUTHORIZED`. Чужой, удалённый или несуществующий идентификатор SHALL возвращать `404 NOT_FOUND` без раскрытия существования базы и её метрик.

#### Scenario: Владелец читает метрики

- **WHEN** авторизованный владелец запрашивает метрики своей активной базы
- **THEN** API возвращает временные ряды этой базы

#### Scenario: Чужая база

- **WHEN** пользователь запрашивает метрики базы другого пользователя
- **THEN** API возвращает `404 NOT_FOUND`

#### Scenario: Запрос без авторизации

- **WHEN** запрос не содержит действующего JWT
- **THEN** API возвращает `401 UNAUTHORIZED`

### Requirement: API не читает историю старше семи дней

API SHALL ограничивать чтение метрик последними семью днями относительно текущего времени базы, даже если более старые строки ещё находятся в таблице.

#### Scenario: В таблице остались старые строки

- **WHEN** таблица содержит снимки старше семи дней
- **THEN** API не возвращает их клиенту

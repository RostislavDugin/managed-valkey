# web-frontend-foundation

## Purpose

Определяет проверяемую основу клиентского приложения Managed Valkey, которую можно запускать, собирать и развивать без смены архитектурных соглашений.

## Requirements

### Requirement: Воспроизводимая установка
Проект SHALL хранить манифест пакетов и lock-файл `pnpm`, достаточные для воспроизводимой установки зависимостей из чистого рабочего дерева.

#### Scenario: Установка из чистого рабочего дерева
- **WHEN** разработчик запускает `pnpm install --frozen-lockfile` в `web` на поддерживаемой версии Node.js
- **THEN** установка завершается без изменения lock-файла

### Requirement: Локальный запуск SPA

Проект SHALL предоставлять команды `pnpm dev` и `web just run`, которые запускают клиентское приложение и передают запросы с путём `/v1` локальному API.

#### Scenario: Запуск сервера разработки

- **WHEN** разработчик запускает `just run` в `web`
- **THEN** корневой маршрут приложения открывается в браузере, а запрос к `/v1` направляется на настроенный адрес API

### Requirement: Производственная сборка

Проект SHALL собирать статические файлы SPA командой `pnpm build`. Рабочий образ Caddy SHALL содержать полученный каталог `web/dist`, отдавать существующие статические файлы и возвращать `index.html` для неизвестного пути клиентского приложения. Рабочая сборка Caddy SHALL подключать скрипт Rybbit `https://rybbit.databasus.com/api/script.js` с идентификатором сайта `5e1f44c518f5`. Локальные команды `pnpm dev`, `pnpm build` и `pnpm preview` SHALL NOT подключать этот скрипт. Бинарник и образ API MUST NOT содержать статические файлы клиентского приложения.

#### Scenario: Сборка приложения

- **WHEN** разработчик запускает `pnpm build`
- **THEN** команда завершается успешно и создаёт каталог статической сборки
- **AND** полученный `index.html` не содержит скрипт Rybbit

#### Scenario: Сборка рабочего образа Caddy

- **WHEN** процесс собирает рабочий образ Caddy с идентификатором сайта Rybbit
- **THEN** полученный `index.html` содержит отложенно загружаемый скрипт `https://rybbit.databasus.com/api/script.js`
- **AND** атрибут `data-site-id` имеет значение `5e1f44c518f5`

#### Scenario: Переход между маршрутами

- **WHEN** пользователь открывает известный маршрут клиентского приложения через Caddy рабочего окружения
- **THEN** Caddy возвращает `index.html`, а приложение отображает соответствующую страницу

#### Scenario: Запрос API

- **WHEN** браузер отправляет запрос на путь `/v1/*`, `/livez` или `/readyz`
- **THEN** Caddy передаёт запрос API вместо поиска файла в `web/dist`

### Requirement: Связь рабочей аналитики с пользовательской сессией

Рабочее клиентское приложение SHALL связывать данные Rybbit с действующей пользовательской сессией, используя UUID аккаунта как постоянный идентификатор пользователя и почту аккаунта как свойство `email`. Отсутствие или отказ Rybbit MUST NOT задерживать проверку пользовательской сессии, переходы между страницами или работу консоли.

#### Scenario: Идентификация действующей сессии

- **WHEN** рабочее приложение загружает действующую пользовательскую сессию и Rybbit доступен
- **THEN** приложение передаёт в Rybbit UUID аккаунта как идентификатор пользователя
- **AND** передаёт почту аккаунта как свойство `email`

#### Scenario: Очистка пользователя на странице входа

- **WHEN** приложение открывает страницу входа без действующей пользовательской сессии
- **THEN** приложение очищает сохранённый идентификатор пользователя Rybbit

#### Scenario: Состояние сессии меняется во время загрузки Rybbit

- **WHEN** пользовательская сессия меняется до завершения асинхронной загрузки Rybbit
- **THEN** после загрузки Rybbit приложение применяет только последнее состояние пользовательской сессии

#### Scenario: Rybbit отсутствует или не загрузился

- **WHEN** скрипт Rybbit отсутствует в локальной сборке или не загрузился в рабочем окружении
- **THEN** приложение продолжает проверку пользовательской сессии и работу консоли без ошибки аналитики

### Requirement: Проверки исходного кода

Каталог `web` SHALL предоставлять публичные команды `run`, `format`, `lint`, `test` и `test-full`. `just format` SHALL форматировать код web и добавлять изменения каталога в индекс Git. `just lint` SHALL запускать статический анализ, проверку границ FSD и типов без изменения файлов. `just test` SHALL запускать быстрые тесты Vitest. Пока отдельных медленных тестов web нет, `just test-full` SHALL выполнять тот же набор и завершаться с тем же результатом.

#### Scenario: Проверка чистого проекта

- **WHEN** разработчик запускает `just lint` и `just test` в неизменённом `web`
- **THEN** обе команды завершаются с нулевым кодом выхода и не меняют рабочее дерево

#### Scenario: Форматирование web

- **WHEN** разработчик запускает `just format` в `web`
- **THEN** форматтер исправляет поддерживаемые файлы и добавляет изменения только каталога `web` в индекс Git

#### Scenario: Ошибка архитектурной зависимости

- **WHEN** исходный модуль нарушает допустимое направление импорта между слоями FSD
- **THEN** `just lint` завершается с ошибкой и указывает нарушивший модуль

#### Scenario: Полный набор пока совпадает с быстрым

- **WHEN** разработчик запускает `just test-full` в `web`
- **THEN** команда выполняет все существующие тесты Vitest без запуска e2e

### Requirement: Минимальная структура FSD
Исходный код SHALL начинаться со слоёв, у которых есть фактическая ответственность, и SHALL NOT содержать пустые слои или срезы, созданные только для предполагаемого будущего использования.

#### Scenario: Проверка начальной структуры
- **WHEN** разработчик просматривает новый каталог `web/src`
- **THEN** каждый созданный слой и срез содержит используемый приложением код и имеет разрешённые FSD зависимости
